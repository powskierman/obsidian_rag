## 📊 When to Use

| ✅ USE FOR | ❌ DON'T USE FOR |
|-----------|-----------------|
| Complex multi-step problems | Simple questions |
| Unclear problem scope | Casual conversation |
| Planning with uncertainty | Quick lookups |
| Need to revise approach | Speed is critical |
| Debugging complex issues | Trivial calculations |

---

## 🔧 Required Parameters

| Parameter | Type | Description | Example |
|-----------|------|-------------|---------|
| `thought` | string | Current thinking step | "Analyzing the problem..." |
| `thought_number` | integer | Current position (1, 2, 3...) | `3` |
| `total_thoughts` | integer | Estimated total (adjustable!) | `7` |
| `next_thought_needed` | boolean | Continue or finish? | `true` / `false` |

---

## ⚙️ Optional Parameters

| Parameter | Type | When to Use |
|-----------|------|-------------|
| `is_revision` | boolean | Correcting earlier thought |
| `revises_thought` | integer | Which thought to revise |
| `branch_from_thought` | integer | Exploring alternative path |
| `branch_id` | string | Naming the branch |
| `needs_more_thoughts` | boolean | Need to extend sequence |

## 📋 Common Patterns

### Linear Flow
```
T1 → T2 → T3 → T4 → T5 ✓
```

### With Revision
```
T1 → T2 → T3
         ↓ (revise T2)
     T4 → T5 ✓
```

### With Branching
```
     → Branch A → T3
T1 → T2
     → Branch B → T4
              ↓
             T5 ✓ (choose B)
```

### Dynamic Adjustment
```
T1 [est: 5] → T2 [adj: 7] → T3 [adj: 6] → ... → T6 ✓
```

## 🎯 Decision Tree: Should I Use Sequential Thinking?

```
Is the problem simple/direct? → YES → Use regular conversation
                              ↓ NO
Can I answer in 1-2 steps? → YES → Use regular conversation
                           ↓ NO
Is speed more important? → YES → Use regular conversation
                        ↓ NO
Is the solution path unclear? → YES → ✅ USE SEQUENTIAL THINKING
Multiple approaches to compare? → YES → ✅ USE SEQUENTIAL THINKING
Need to revise as I go? → YES → ✅ USE SEQUENTIAL THINKING
Complex verification needed? → YES → ✅ USE SEQUENTIAL THINKING
```

## 🔄 Typical Flow Template

```
Thought 1: Understand the problem
- What are we solving?
- What are the constraints?
- Initial complexity estimate

Thought 2-4: Explore and analyze
- Consider approaches
- Identify issues
- Revise if needed

Thought N-1: Generate solution
- Propose complete solution
- Address all requirements

Thought N: Verify and conclude
- Verify against constraints
- Confirm completeness
- Set next_thought_needed = false
```

---

## ✅ Quality Checklist

Before setting `next_thought_needed = false`:

- [ ] Problem fully understood
- [ ] All constraints identified
- [ ] Solution addresses root cause
- [ ] Solution verified
- [ ] Edge cases considered
- [ ] Alternatives evaluated
- [ ] No outstanding doubts

---

## 🚨 Common Mistakes

| Mistake | Fix |
|---------|-----|
| Finishing too early | Add verification step |
| Not revising when needed | Use `is_revision = true` |
| Too many branches | Limit to 2-3, synthesize |
| Unclear revisions | State what changed and why |
| Scope creep | Stay focused on original problem |

---

## 💡 Pro Tips

1. **Start with 5-7 thoughts** - Adjust as needed
2. **Batch related analyses** - Combine when clear
3. **Verify before finishing** - Always double-check
4. **Use clear branch names** - "async_approach" not "option2"
5. **Skip obvious steps** - Don't narrate everything
6. **Express uncertainty** - "I'm not certain..." is OK
7. **Filter irrelevant info** - Explicitly note what you're ignoring

---

## 📐 Best Practices

### Starting
- Estimate conservatively (5-7 thoughts)
- State all constraints upfront
- Plan your approach

### During
- Adjust `total_thoughts` dynamically
- Revise when assumptions prove wrong
- Branch for alternatives
- Add checkpoints every 5 thoughts (if long)

### Finishing
- Verify solution against requirements
- Check edge cases
- Only finish when truly satisfied

## 🆘 Troubleshooting

| Problem | Solution |
|---------|----------|
| Tool not found | Check docker-gateway is running |
| Thoughts disconnected | Reference previous thoughts explicitly |
| Too many thoughts | Check for scope creep, batch analyses |
| Unsure when to stop | Use quality checklist above |
| Branches too complex | Limit to 2-3 branches max |
