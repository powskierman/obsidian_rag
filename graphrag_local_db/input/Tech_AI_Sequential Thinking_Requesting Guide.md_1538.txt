## How to Request Sequential Thinking

### Simple Direct Requests

The easiest way is to simply ask:

```
"Can you use sequential thinking to debug why my API is slow?"

"Please use sequential thinking to design an algorithm for this problem."

"I need you to think through this complex decision step by step."

"Use sequential thinking to analyze this architecture proposal."
```

**When Claude will activate it**: When you explicitly mention "sequential thinking" or "step by step" for complex problems.

---

## Alternative Phrasings

You can also request it with:

```
"Walk me through your reasoning step by step for this problem."

"Think out loud while solving this."

"Show me your thought process for debugging this issue."

"Break down your analysis of this system."

"Reason through this complex decision with me."
```

**Tip**: Claude recognizes when a problem is complex enough to warrant Sequential Thinking.

---

## What to Include in Your Request

### 1. The Problem Statement

Be clear about what you need:

```
✅ Good: "My React app loads slowly on mobile. Initial bundle is 5MB. Use sequential thinking to identify bottlenecks and propose solutions."

❌ Vague: "My app is slow, help."
```

---

### 2. Relevant Context

Provide important details:

```
✅ Good: "API returns 500 errors intermittently (2% of requests). Happens across all endpoints. Logs show 'Connection timeout'. Multiple microservices involved. Use sequential thinking to diagnose."

❌ Missing context: "API has errors sometimes."
```

---

### 3. Constraints (If Any)

State limitations upfront:

```
✅ Good: "Design a caching strategy for high-traffic API. Must handle 10K req/s, keep latency under 100ms, and data updates hourly. Use sequential thinking."

❌ Without constraints: "Design a caching strategy."
```

---

### 4. Desired Outcome

What you want at the end:

```
✅ Good: "Use sequential thinking to evaluate whether we should migrate to microservices. I need a recommendation with clear reasoning."

❌ Unclear: "Think about microservices."
```

---

## Examples of Good Requests

### For Debugging

```
"My production database queries are timing out intermittently. Query logs show timeouts on user_posts table. Connection pool shows 60% utilization. Use sequential thinking to identify the root cause."
```

---

### For Design

```
"I need to design an authentication system for a multi-tenant SaaS app. Requirements: Support SSO, handle 50K users, must be PCI compliant. Use sequential thinking to propose an architecture."
```

---

### For Analysis

```
"Analyze this system architecture proposal [attach diagram]. Consider scalability, maintainability, and cost. Use sequential thinking to provide detailed feedback."
```

---

### For Decision-Making

```
"Should we use PostgreSQL or MongoDB for our analytics platform? We're processing 1TB of time-series data daily, need complex aggregations, and have a team experienced with SQL. Use sequential thinking to compare options."
```

## What to Expect

### 1. Claude Will Show Each Thought

You'll see the reasoning unfold:

```
Thought 1: Understanding the problem...
Thought 2: Analyzing potential causes...
Thought 3: Actually, let me reconsider...
Thought 4: Testing this hypothesis...
Thought 5: Verified! Here's the solution...
```

---

### 2. Claude May Revise Its Thinking

This is normal and good:

```
Thought 3: The issue is the database queries
Thought 4: Actually, after checking metrics, it's the cache configuration [REVISION]
```

---

### 3. Claude May Explore Alternatives

Through branching:

```
Thought 3 [Approach A]: Using synchronous processing...
Thought 4 [Approach B]: Using async queues instead...
Thought 5: Comparing approaches → B is better
```

---

### 4. The Plan May Adjust

Claude might extend or shorten:

```
Thought 1 [1/5]: Initial analysis...
Thought 3 [3/7]: This is more complex, extending to 7 thoughts
Thought 5 [5/6]: Found shortcut, reducing to 6 thoughts
```

---

## Interacting During Sequential Thinking

### Let It Complete

Generally, let Claude finish the sequence before responding. You'll get a complete, well-reasoned answer.

---

### Provide Feedback if Needed

If Claude is heading in the wrong direction, you can interject:

```
User: "Actually, the database metrics look fine. Focus on the network layer instead."

Claude: "Ah, thanks for the correction. Let me revise my approach..."
```

---

### Ask Follow-up Questions After

Once Claude finishes, you can:

```
"Can you elaborate on Thought 5 about the caching strategy?"

"What would change if we had budget constraints?"

"Can you explore the alternative you mentioned in Thought 3?"
```

## When NOT to Request It

### Simple Questions

```
❌ "Use sequential thinking to tell me what 2+2 is"
✅ "What's 2+2?"
```

---

### Quick Lookups

```
❌ "Use sequential thinking to find the capital of France"
✅ "What's the capital of France?"
```

---

### Casual Chat

```
❌ "Use sequential thinking to chat about the weather"
✅ "How's the weather been?"
```

---

### When Time is Critical

```
❌ "Production is down! Use sequential thinking..."
✅ "Production is down! Quick diagnosis needed!" 
    [Then maybe detailed analysis later]
```

## Tips for Best Results

### Tip 1: Be Specific About Complexity

```
✅ "This is a complex problem with multiple interdependencies - use sequential thinking"
❌ "Figure this out" [Claude will choose appropriate approach]
```

---

### Tip 2: Provide All Context Upfront

Don't make Claude guess:

```
✅ "Database: PostgreSQL 14, 10M rows, running on AWS RDS t3.large, queries timing out during peak hours..."

❌ "Database is slow" [Claude will need to ask questions]
```

---

### Tip 3: State Your Goal Clearly

```
✅ "I need a solution I can implement this week with minimal risk"

❌ Unstated constraints [Claude might propose complex solution]
```

---

### Tip 4: Indicate Uncertainty

If you're unsure about something:

```
"I think the issue is in the cache layer, but I'm not certain. Use sequential thinking to investigate."
```

---

### Tip 5: Ask for Explanation

If you want to learn:

```
"Use sequential thinking to solve this, and explain your reasoning at each step so I can learn the approach."
```

## Request Templates

### Template: Debugging

```
"I'm experiencing [PROBLEM]. 
Context: [RELEVANT DETAILS]
What I've tried: [ATTEMPTED SOLUTIONS]
Constraints: [ANY LIMITATIONS]
Use sequential thinking to diagnose the root cause."
```

---

### Template: Design

```
"I need to design [SYSTEM/COMPONENT].
Requirements: [MUST-HAVES]
Constraints: [LIMITATIONS]
Current context: [EXISTING SETUP]
Use sequential thinking to propose an architecture."
```

---

### Template: Decision

```
"I need to decide between [OPTION A] and [OPTION B].
Context: [SITUATION]
Criteria: [WHAT MATTERS]
Trade-offs I'm aware of: [KNOWN PROS/CONS]
Use sequential thinking to analyze and recommend."
```

---

### Template: Analysis

```
"Please analyze [THING TO ANALYZE].
Focus on: [SPECIFIC ASPECTS]
Constraints: [SCOPE LIMITATIONS]
Use sequential thinking to provide detailed analysis."
```

## Understanding the Response

### Progress Indicators

```
[1/5] = Early in process (20%)
[3/5] = Halfway (60%)
[5/5] = Complete (100%)
```

---

### Revision Markers

```
[REVISION] or "Actually, ..." = Course correction
```

---

### Branch Indicators

```
[Branch A] = Exploring option A
[Branch B] = Exploring option B
```

---

### Verification Markers

```
✓ = Verified/confirmed
✗ = Ruled out/rejected
```

---

## Common Questions

### "How long will it take?"

- Simple problems: 30-60 seconds
- Complex problems: 1-2 minutes
- Very complex: 2-3 minutes

---

### "Can I stop it mid-way?"

Yes, but you'll get incomplete analysis. Better to let it finish.

---

### "Can I request specific # of thoughts?"

Not directly, but you can indicate complexity:

```
"This is a quick question, just a few thoughts needed"
"This is very complex, thorough analysis needed"
```

---

### "What if the answer is wrong?"

Point out the issue:

```
"Actually, the database metrics show X, not Y. Can you revise?"
```

Claude will adjust and continue.

---

## Success Indicators

You've made a good request if:

✅ Problem is clearly stated
✅ Context is provided
✅ Constraints are known
✅ Desired outcome is clear
✅ Complexity warrants the tool
