## 🚨 When to Use This Document

### Immediate Rollback Triggers:
- Vault won't open or crashes repeatedly
- Mass link breakage detected (>10 broken links)
- Files missing or corrupted
- Plugin failures after changes
- Unexpected behavior in critical workflows
- Data loss suspected
- Automation causing damage

### Consider Rollback:
- Changes feel overwhelming or wrong
- Decreased productivity/increased friction
- Regret major decisions
- Can't find important notes
- Workflow disruption lasting >24 hours

## ⚡ Emergency Quick Rollback

**If the vault is critically broken, follow these steps immediately:**

### 1. STOP All Activity
- [ ] Close Obsidian completely
- [ ] Stop any running n8n workflows
- [ ] Do NOT make any more changes
- [ ] Document what you were doing when the problem occurred

### 2. Assess Damage
```markdown
What happened: [Description]
When: [Date/Time]
What was I doing: [Phase/Task]
Files affected: [Number/Names]
Error messages: [If any]
Can vault still open: Yes / No
```

### 3. Quick Recovery Options

**Option A: Restore from today's backup** (if available)
```bash
# Close Obsidian first
# Copy backup to vault location
# Restart Obsidian
```

**Option B: Use Obsidian's built-in recovery**
- Settings → Files & Links → Check "Deleted files"
- .trash folder may contain recently deleted files

**Option C: Git rollback** (if using version control)
```bash
git log --oneline  # Find last good commit
git reset --hard <commit-hash>
```

## 📋 Rollback Procedures by Scenario

### Scenario 1: Broken Links After Moving Files

**Symptoms:**
- Links showing as unresolved
- "Link to note" not working
- Broken references in MoCs

**Rollback Steps:**

1. **Assess scope**
   ```dataview
   TABLE file.outlinks as "Broken Links"
   WHERE length(file.outlinks) > 0
   AND any(map(file.outlinks, (link) => !link.path))
   ```

2. **If <10 broken links:**
   - [ ] Fix manually using Obsidian's "Update internal links"
   - [ ] Document which files were moved
   - [ ] Verify fixes worked

3. **If >10 broken links:**
   - [ ] Stop and restore from backup
   - [ ] Review what went wrong
   - [ ] Plan better approach using Obsidian's move feature

4. **Prevent recurrence:**
   - Always use Obsidian's built-in move (not file system)
   - Enable Settings → Files & Links → "Automatically update internal links"

---

### Scenario 2: Corrupted or Missing Files

**Symptoms:**
- Files won't open
- Content appears garbled
- Files missing from vault
- Sync errors

**Rollback Steps:**

1. **Immediate action:**
   - [ ] Note which files are affected
   - [ ] Check .trash folder in vault
   - [ ] Check OS recycle bin/trash

2. **Recovery attempts (in order):**
   
   **A. Restore from .obsidian sync:**
   - Check `.obsidian/workspace` for recent file references
   - Look in Obsidian sync history (if using)
   
   **B. Restore from backup:**
   ```bash
   # Close Obsidian
   # Identify missing/corrupted files
   # Copy ONLY those files from backup
   # Restart Obsidian
   ```
   
   **C. Restore from Git:**
   ```bash
   git status  # Check what changed
   git checkout <commit-hash> -- path/to/file.md
   ```
   
   **D. Full vault restore:**
   - Last resort only
   - Follow "Complete Vault Restore" procedure below

---

### Scenario 3: Frontmatter Corruption

**Symptoms:**
- Notes not appearing in queries
- Template errors
- YAML parsing errors
- Tags not working

**Rollback Steps:**

1. **Identify affected notes:**
   - Look for YAML error messages
   - Check recently modified notes
   - Run query to find malformed frontmatter

2. **Fix individual notes:**
   ```yaml
   # Correct format:
   ---
   key: value
   tags:
     - tag1
     - tag2
   ---
   ```

3. **Bulk rollback if needed:**
   - [ ] Get list of all notes modified in phase
   - [ ] Restore frontmatter from backup
   - [ ] Use text comparison tool to verify
   - [ ] Test with Dataview queries

4. **Prevention:**
   - Test frontmatter changes on 5 notes first
   - Validate YAML syntax before bulk operations
   - Keep backup of all notes before frontmatter changes

---

### Scenario 4: n8n Automation Gone Wrong

**Symptoms:**
- Unwanted files created
- Incorrect modifications to notes
- Bulk changes that shouldn't have happened
- Workflow running on wrong files

**Rollback Steps:**

1. **STOP THE WORKFLOW IMMEDIATELY:**
   - [ ] Open n8n
   - [ ] Deactivate the problematic workflow
   - [ ] Check execution history to see what happened

2. **Assess damage:**
   ```markdown
   Workflow name: [Name]
   Last execution: [Time]
   Files affected: [Number]
   Type of changes: [Created/Modified/Deleted]
   ```

3. **Rollback actions:**
   
   **If files created:**
   - [ ] Review list of files created
   - [ ] Delete if unwanted
   - [ ] Check if they overwrote existing files
   
   **If files modified:**
   - [ ] Get list of modified files from n8n logs
   - [ ] Restore those specific files from backup
   - [ ] Verify restoration successful
   
   **If files deleted:**
   - [ ] Check .trash folder
   - [ ] Restore from backup immediately

4. **Fix the workflow:**
   - [ ] Identify the bug/misconfiguration
   - [ ] Test on test vault first
   - [ ] Document what went wrong
   - [ ] Add safeguards (file count limits, confirmation steps)

---

### Scenario 5: Plugin Conflicts After Changes

**Symptoms:**
- Obsidian crashes or freezes
- Plugins not loading
- Error messages at startup
- Features not working

**Rollback Steps:**

1. **Safe mode startup:**
   - [ ] Close Obsidian
   - [ ] Start Obsidian in Safe Mode (hold Ctrl/Cmd while opening)
   - [ ] This disables all community plugins

2. **Identify culprit:**
   - [ ] Re-enable plugins one by one
   - [ ] Test after each enable
   - [ ] Note which plugin causes the issue

3. **Resolve:**
   - [ ] Update problematic plugin
   - [ ] Or disable if not critical
   - [ ] Check if vault changes broke plugin compatibility
   - [ ] May need to restore .obsidian/plugins folder from backup

---

### Scenario 6: Regret Major Decisions

**Symptoms:**
- New organization feels wrong
- Can't find things anymore
- Workflow is disrupted
- Missing the old way

**Rollback Steps:**

1. **Don't panic - assess objectively:**
   - [ ] Give it 48 hours before rolling back
   - [ ] List specific problems (not just "feels wrong")
   - [ ] Check if it's just unfamiliarity
   - [ ] Ask: "Is this truly worse or just different?"

2. **Partial rollback option:**
   - [ ] Identify what specifically isn't working
   - [ ] Restore only those elements
   - [ ] Keep successful changes
   - [ ] Hybrid approach often best

3. **Full rollback:**
   ```markdown
   Decision: Full rollback to [date]
   Reason: [Specific reasons]
   What to preserve: [Any good changes]
   Lessons learned: [Document]
   ```
   - [ ] Follow "Complete Vault Restore" below
   - [ ] Extract any valuable work done since
   - [ ] Document why it didn't work

## 🔄 Complete Vault Restore Procedure

**Use this for catastrophic failures only.**

### Prerequisites:
- [ ] Valid backup exists
- [ ] Backup date identified
- [ ] Current vault state documented
- [ ] Any valuable recent work saved separately

### Steps:

1. **Prepare:**
   ```bash
   # Create emergency backup of current state
   # Even if broken, it might have recent notes
   cp -r /path/to/vault /path/to/emergency-backup-[date]
   ```

2. **Close Obsidian completely:**
   - [ ] Quit application
   - [ ] Verify no Obsidian processes running
   - [ ] Close any open note editors

3. **Backup current state:**
   - [ ] Rename current vault folder
   - [ ] Don't delete yet (may need to recover recent work)
   ```bash
   mv MyVault MyVault-broken-2025-10-16
   ```

4. **Restore from backup:**
   ```bash
   # Copy backup to original location
   cp -r /path/to/backup/MyVault /path/to/MyVault
   
   # Verify file count matches
   # Spot-check a few important files
   ```

5. **Restart Obsidian:**
   - [ ] Open vault
   - [ ] Verify it works
   - [ ] Check recent notes are there
   - [ ] Test core workflows

6. **Recover recent work:**
   - [ ] Compare broken vault with backup
   - [ ] Identify any notes created/modified after backup
   - [ ] Manually copy those notes over
   - [ ] Verify no corruption

7. **Post-restore verification:**
   ```markdown
   - [ ] Can open vault
   - [ ] All plugins working
   - [ ] Critical workflows functional
   - [ ] No error messages
   - [ ] Recent notes accessible
   - [ ] Links working
   - [ ] Search working
   - [ ] Daily workflow restored
   ```

8. **Document what happened:**
   - Create incident report
   - Note date/time of failure
   - Describe what caused it
   - What was lost (if anything)
   - What was learned
   - How to prevent recurrence

## 🛠️ Recovery Tools & Resources

### Built-in Obsidian Features:
- **File Recovery**: `.trash` folder in vault
- **Sync History**: If using Obsidian Sync
- **Safe Mode**: Start with plugins disabled
- **Auto-backup**: Check .obsidian/workspace.json for references

### External Tools:
```markdown
**File Recovery:**
- PhotoRec (cross-platform)
- TestDisk (Linux/Mac)
- Recuva (Windows)

**Git Recovery:**
- git reflog (shows all actions)
- git fsck (finds unreachable objects)

**Text Comparison:**
- Beyond Compare
- Meld (free)
- diff command (built-in)

**Backup Tools:**
- rsync (automated backups)
- Time Machine (Mac)
- File History (Windows)
```

### Useful Commands:

**Find recently modified files:**
```bash
# Files modified in last 24 hours
find . -name "*.md" -mtime -1

# Files modified in last week
find . -name "*.md" -mtime -7
```

**Count files:**
```bash
# Total markdown files
find . -name "*.md" | wc -l
```

**Search for content:**
```bash
# Find all files containing text
grep -r "search term" --include="*.md"
```

## 📊 Rollback Decision Matrix

| Severity | Scope | Immediate Action | Restore Level |
|----------|-------|------------------|---------------|
| **Low** | Few files (<5) | Manual fix | No restore needed |
| **Medium** | Section (5-50) | Restore specific files | Partial restore |
| **High** | Multiple areas (50+) | Stop all work | Consider full restore |
| **Critical** | Vault unusable | Emergency procedures | Full restore |

## 🎯 Prevention Best Practices

**Before Every Major Change:**
1. [ ] Create backup
2. [ ] Verify backup works
3. [ ] Test on small subset first
4. [ ] Document what you're about to do
5. [ ] Have rollback plan ready

**During Changes:**
1. [ ] Work incrementally (small batches)
2. [ ] Verify after each batch
3. [ ] Stop if unexpected behavior
4. [ ] Keep Obsidian open to verify links
5. [ ] Don't rush through major changes

**After Changes:**
1. [ ] Wait 24 hours before next major change
2. [ ] Test workflows thoroughly
3. [ ] Create new backup of successful changes
4. [ ] Document what worked/didn't
5. [ ] Update procedures based on experience
