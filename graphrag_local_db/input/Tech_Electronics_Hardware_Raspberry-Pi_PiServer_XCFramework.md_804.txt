### Notes
- Apple has been moving away from "fat" frameworks in favor of XCFrameworks, especially since the introduction of Apple Silicon Macs. Using an XCFramework is the recommended approach going forward.
-  An XCFramework allows you to bundle a binary framework or library for multiple platforms and architectures into a single distributable package.

Here's how you can create an XCFramework:
- **Build for iOS Devices**:
    `xcodebuild -project HassFramework.xcodeproj -scheme HassFramework -configuration Release -sdk iphoneos BUILD_DIR=./build BUILD_ROOT=./build clean build`
- **Build for iOS Simulator**:
      `xcodebuild -project YourProject.xcodeproj -scheme HassFramework -configuration Release -sdk iphonesimulator ARCHS='x86_64 arm64' BUILD_DIR=./build BUILD_ROOT=./build clean build`
- For M1 Macs, the simulator uses the `arm64` architecture, and for Intel Macs, it uses `x86_64`. You can include both if you want universal support.
- **If Building for the Apple Watch**
	- Adjust Module Name in Framework: When building the framework for watchOS, make sure that the internal module name matches the iOS version. This is typically defined in the framework's project settings under "Product Module Name" or similar. The module name should be `HassFramework` for both iOS and watchOS builds.
- **Create the XCFramework**:
    `xcodebuild -create-xcframework -framework build/Release-iphoneos/HassFramework.framework -framework build/Release-iphonesimulator/HassFramework.framework -output HassFramework.xcframework`
- **Add the XCFramework to Your Project**:
    - Drag `HassFramework.xcframework` into your project in Xcode.
    - Ensure that you add it to the appropriate targets and that it's included in any necessary build phases.
- **Update Import Statements**:
    - If needed, update your import statements in Swift files from `import HassFramework` to match the new module name if it has changed.
