### Notes
1. Nodes:

Nodes are the basic building blocks in Node-Red. Each node represents a specific functionality, such as:

	•	Input nodes: Receive data (e.g., HTTP, MQTT, or sensor inputs).
	•	Output nodes: Send data (e.g., to devices, APIs, or databases).
	•	Processing nodes: Modify or analyze data (e.g., function, switch, or change nodes).

Nodes can be connected together to form flows, and you can configure their behavior through their individual settings.

2. Flows:

A flow is a collection of nodes wired together to perform a specific task or set of tasks. You can think of a flow as a unit of automation or logic that operates independently but may interact with other flows through global context or messages. Flows are visual representations of your automation logic, and you can organize them on different tabs within the Node-Red editor.

	•	Tabs in the editor: Each tab in the Node-Red editor represents a separate flow, making it easier to organize different parts of your project visually. For example, one tab might handle lighting automation, another might deal with temperature control, etc.
	•	Multiple flows: Node-Red allows you to have multiple flows running simultaneously, and they can communicate with each other using the global context or by sending messages between them.

3. Context Storage:

Node-Red has three main levels of context that help manage data and state across nodes, flows, or globally in the project: Node, Flow and Global

[[Node-Red Context Types]]

The context hierarchy helps keep the data localized when needed and shared across larger parts of your project when required.

4. Subflows:

	•	A subflow is a reusable flow that can be encapsulated and used multiple times across different flows. **You can think of a subflow like a function or a class in traditional programming**: it’s a self-contained unit that can be called and reused in multiple places, reducing redundancy.
	•	Subflows are great for organizing repeated logic or tasks (like error handling, logging, or common API calls) that you want to use across different parts of your project.
	•	If you update the subflow, all instances of that subflow within your project will be updated automatically, making it easier to maintain.

5. Projects:

	•	Projects are a higher-level organizational feature in Node-Red. **A project allows you to manage and version-control your flows**, making it easier to collaborate on a complex Node-Red deployment or manage multiple deployments in a structured way.
	•	**Projects store the full set of flows, subflows, and configurations in a version-controlled format, typically with Git integration.** This allows for:
	•	Version Control: Track changes to your flows and roll back to previous versions if needed.
	•	Collaboration: Work on flows collaboratively with multiple team members.
	•	Deployment Management: Use Git to manage different branches, enabling development, testing, and production environments.

6. Environment Variables:

	•	Node-Red allows the use of environment variables at both the flow and project levels, providing a way to dynamically configure nodes, flows, or the entire project without hard-coding values.
	•	Environment variables are typically used to set up things like API keys, device IDs, or database credentials, making it easier to change configurations across different environments (e.g., development vs. production).

7. File System Organization:

The underlying file system structure of a Node-Red instance helps organize flows and configuration files:

	•	Flows file (flows.json): Stores the visual flows created in the editor.
	•	Credentials file (flows_cred.json): Stores any credentials securely used by nodes (such as API tokens).
	•	Settings file (settings.js): A configuration file that allows you to customize Node-Red’s runtime behavior, such as adding custom nodes, managing context storage (memory or file-based), and enabling project management.

8. Groups (Node-Red v2.0+):

	•	**[[Node-Red Groups]] allow you to organize nodes visually within a flow by grouping them together.** This makes it easier to manage complex flows by visually clustering related nodes.
	•	You can apply settings to the entire group (e.g., hiding or disabling all nodes in the group at once), improving the manageability of larger projects.
