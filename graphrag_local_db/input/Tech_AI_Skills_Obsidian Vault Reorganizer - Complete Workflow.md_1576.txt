### Main Idea
- Detailed step-by-step workflow for the 5-phase vault reorganization process
- Each phase includes goals, processes, safety measures, and expected outputs
- Designed for interactive execution with user checkpoints

### Phase 1: Vault Discovery & Analysis

**Goal:** Build complete understanding of vault state

**Step 1.1: Get Vault Statistics**
```
obsidian_vault_stats()
```
- Record total notes count
- Note entity relationships
- Understand knowledge graph structure

**Step 1.2: List All Files**
```
obsidian_list_files_in_vault()
```
- Build complete file inventory
- Count total .md files
- Identify existing folder structure

**Step 1.3: Batch Analyze Notes**
```
obsidian_batch_get_file_contents(filepaths=[...])
```
Process 10-20 files at a time:
- Check if empty (< 20 characters)
- Check for frontmatter (starts with `---`)
- Extract existing tags (#tag format)
- Extract categories from frontmatter
- Extract wikilinks

**Step 1.4: Identify Orphaned Notes**
```
obsidian_graph_query(query="notes with zero backlinks")
```
- Query for notes with zero incoming links
- Filter out intentional orphans (templates, daily notes)
- Create orphaned notes list

**Phase 1 Output:**
- Total files: ___
- Empty notes: ___
- Notes missing frontmatter: ___
- Orphaned notes: ___
- Well-formed notes: ___

### Phase 2: Empty Note Cleanup

**Goal:** Remove truly empty or useless notes

**Deletion Criteria:**
- File is completely empty
- File has only whitespace  
- File has < 20 characters and no frontmatter
- User confirms deletion

**Process:**

**Step 2.1: Review Empty Notes**
- Present list of empty notes to user
- Show preview (first 100 chars) of each
- Get confirmation: "Delete all (Y/n), review each (r), or skip (s)?"

**Step 2.2: Delete Empty Notes**
```
obsidian_delete_file(filepath="path/to/note.md", confirm=True)
```
For each empty note:
- Preview content one last time
- Call delete with confirm=True
- Log deletion with content snapshot
- Verify deletion

**Step 2.3: Update Inventory**
- Remove deleted files from working list
- Update file counts
- Save deletion log

**Safety Measures:**
- Never auto-delete without user approval
- Keep deletion log with timestamps and content
- Provide file preview before deletion if requested

### Phase 3: Frontmatter Standardization

**Goal:** Add consistent frontmatter to all notes

**Default Frontmatter Template:**
```yaml
---
title: {{filename}}
created: {{date}}
modified: {{date}}
tags: []
categories: []
backlinks: []
status: draft
---
```

**Process:**

**Step 3.1: For Notes Without Frontmatter**

1. Read full content:
```
obsidian_get_file_contents(filepath="note.md")
```

2. Generate appropriate metadata:
   - Extract inline tags (#tag format)
   - Infer categories from content keywords
   - Use filename as title (cleaned)
   - Set default dates

3. Add frontmatter:
```
obsidian_patch_content(
    filepath="note.md",
    target_type="frontmatter",
    operation="prepend",
    content="---\\ntitle: Note\\ntags: []\\ncategories: []\\n---\\n"
)
```

**Step 3.2: For Existing Frontmatter**

Update missing fields only:
```
obsidian_patch_content(
    filepath="note.md",
    target_type="frontmatter",
    operation="replace",
    target="categories",
    content='["suggested", "categories"]'
)
```

**Batch Processing:**
- Process 10 notes at a time
- Show progress indicator
- Allow user to review/modify template per category
- Preserve existing metadata

### Phase 4: Backlink Identification & Addition

**Goal:** Connect orphaned notes to the knowledge graph

**Process:**

**Step 4.1: Find Orphaned Notes**
```
obsidian_graph_query(query="notes with zero backlinks")
```
- Exclude templates, daily notes, intentional orphans

**Step 4.2: For Each Orphaned Note**

1. Extract key concepts from content:
   - Use title and first paragraph
   - Remove stopwords
   - Identify top 5 concepts

2. Semantic search for similar notes:
```
obsidian_simple_search(
    query="key concepts here",
    n_results=10
)
```

3. Analyze results:
   - Top 5-10 most relevant notes
   - Rank by semantic similarity score
   - Identify potential parent/related notes

**Step 4.3: Add Backlinks to Frontmatter**
```
obsidian_patch_content(
    filepath="orphan.md",
    target_type="frontmatter",
    operation="replace",
    target="backlinks",
    content='["[[Note 1]]", "[[Note 2]]", "[[Note 3]]"]'
)
```

**Step 4.4: Optional - Create Bidirectional Links**
- Search related notes for appropriate insertion points
- Add "See also" sections
- Insert bidirectional links

**Smart Strategies:**
- Use `obsidian_vault_stats` to identify hub notes (highly connected)
- Prefer linking to hub notes for better integration
- Group notes by topic clusters before linking
- Suggest backlinks but require user approval

### Phase 5: Categorical Folder Organization

**Goal:** Organize notes into meaningful folder structure

**Process:**

**Step 5.1: Analyze Note Categories**
```
obsidian_complex_search(
    query={"var": "frontmatter.categories"}
)
```
- Aggregate all `categories` and `tags` fields
- Build category frequency map
- Identify major categories (>10 notes)
- Identify minor categories
- Create category hierarchy

**Step 5.2: Design Folder Structure**

Example structure:
```
/Projects
  /Active
  /Archived
  /Ideas
/Knowledge
  /Technical
  /Research
  /Learning
/Personal
  /Journal
  /Goals
  /Reflections
/Reference
  /Templates
  /Resources
  /Archive
```

- Present to user for approval/modification
- Finalize folder mapping

**Step 5.3: Create Category Mapping**

For each note, determine target folder from:
- Primary category in frontmatter
- Semantic analysis of content
- Existing folder location (if sensible)
- Handle notes with multiple categories (use primary)

**Step 5.4: Create Folders**
```bash
mkdir -p "/vault/path/Category/Subcategory"
```

**Step 5.5: Move Files**
```bash
mv "old/path/note.md" "new/path/Category/note.md"
```
- Preview moves before executing
- Move in category batches (20 at a time)
- Log each move (old → new path)
- Verify file exists at new location

**Step 5.6: Update Wikilinks**

After moving files:
1. Find all wikilinks:
```
obsidian_complex_search(query with wikilink pattern)
```

2. Update references to moved files:
   - Old: `[[note]]`
   - New: `[[Subfolder/note]]` (if needed by your setup)

3. Verify with:
```
obsidian_graph_query(query="check for broken links")
```

**Batch Organization:**
- Present folder structure for approval first
- Move files in category batches
- Provide undo log (original → new paths)
- Verify link integrity after each batch

### Notes

**Efficiency Optimizations:**
- Use `obsidian_batch_get_file_contents` for reading 10-20 files simultaneously
- Group similar operations (all frontmatter additions, then all moves)
- Cache file content analysis to avoid redundant reads
- Use semantic search (RAG) instead of keyword matching
- Use JsonLogic for precise metadata queries

**Safety & Rollback:**
- Remind user to backup vault before starting
- Create operation log: `_reorganization_log_TIMESTAMP.md`
- Log every operation with timestamp and details
- Keep detailed log of all changes for rollback
- Provide preview before batch operations

**Performance Notes:**
- For large vaults (1000+ notes): Process in batches of 50-100
- For small vaults (<100 notes): Can process all at once
- Use `obsidian_complex_search` instead of loading all files
- Consider running overnight for very large vaults
