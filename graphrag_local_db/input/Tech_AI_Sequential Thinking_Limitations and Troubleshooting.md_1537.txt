## What Sequential Thinking Cannot Do

### ❌ Cannot Access External State

**Limitation**: Each thought is independent.

**Cannot do**:
```javascript
// This won't work
Thought 1: const result = calculateSomething();
Thought 2: Use result from Thought 1
```

**Workaround**: Maintain context through thought content itself:
```
Thought 1: Calculated value is 42
Thought 2: Using the value 42 from previous thought...
```

---

### ❌ Cannot Execute Code

**Limitation**: Sequential Thinking is for reasoning, not execution.

**Cannot do**:
- Run code snippets
- Query databases  
- Test hypotheses with actual data
- Validate syntax

**Workaround**: Use complementary tools:
```
1. Sequential Thinking → Design approach
2. Analysis Tool (REPL) → Test implementation
3. Sequential Thinking → Verify results
```

---

### ❌ Not Suitable for Simple Questions

**Limitation**: Adds overhead for trivial problems.

**Don't use for**:
- "What's 2+2?"
- "Capital of France?"
- "How do I declare a variable in Python?"

**Use instead**: Regular conversation

---

### ❌ Cannot Save Progress

**Limitation**: No persistent state between thoughts.

**Cannot do**:
- Save intermediate results
- Resume from checkpoint
- Share state with artifacts

**Workaround**: Complete the thinking in one session.

---

## Performance Considerations

### ⚠️ Token Usage

**Issue**: Each thought consumes tokens.

**Impact**:
- Long thinking sessions are expensive
- Each thought requires input + output tokens
- Typical session: 5-10 thoughts = 2000-5000 tokens

**Mitigation**:
- Use judiciously for complex problems
- Don't overuse for simple queries
- Batch related analyses in single thoughts

---

### ⚠️ Latency

**Issue**: Multiple tool calls add latency.

**Impact**:
- Each thought requires a round trip
- Typical thought: 2-5 seconds
- Complete session: 30-60+ seconds

**When acceptable**:
- Complex debugging (worth the wait)
- Strategic decisions (time well spent)
- Deep analysis (thoroughness > speed)

**When problematic**:
- Quick questions
- Casual conversation
- Time-sensitive queries

---

### ⚠️ Context Window

**Issue**: Very long thought sequences can consume context.

**Impact**:
- After 15-20 thoughts, context pressure increases
- May need to summarize earlier thoughts
- Risk of losing important details

**Mitigation**:
- Keep thoughts focused and concise
- Aim for 5-10 thoughts for most problems
- Reserve 15+ thought sequences for truly complex issues

---

## Common Issues & Solutions

### Issue 1: Premature Conclusion

**Symptom**: Finishing before thorough verification.

**Example**:
```
T5: Found solution! (next_thought_needed = false)
[But didn't verify against constraints]
```

**Solution**: Always add verification step:
```
T5: Proposed solution
T6: Verify against all constraints
T7: Confirmed complete (next_thought_needed = false)
```

---

### Issue 2: Analysis Paralysis

**Symptom**: Too many thoughts without progress.

**Example**:
```
T10: Still exploring options...
T11: Another consideration...
T12: But what about...
```

**Solution**: Set decision point:
```
T8: Will decide by T10 based on current info
T9: Final analysis
T10: Decision made (next_thought_needed = false)
```

---

### Issue 3: Lost in Branches

**Symptom**: Too many branches without synthesis.

**Example**:
```
Branch A, Branch B, Branch C, Branch D...
[Never compared or chose]
```

**Solution**: Limit branches and synthesize:
```
T5 [Branch A]
T6 [Branch B]  
T7: Compare A and B → Choose B
```

---

### Issue 4: Revision Confusion

**Symptom**: Unclear what's being revised.

**Example**:
```
T6: Actually that was wrong (is_revision=true)
[But which thought? What was wrong?]
```

**Solution**: Be explicit:
```
T6: My assumption in T3 about the database was wrong (is_revision=true, revises_thought=3). The actual bottleneck is...
```

---

### Issue 5: Scope Creep

**Symptom**: Original problem expands uncontrollably.

**Example**:
```
T1: Debug API slowness
T5: Also need to redesign architecture
T8: And update deployment process
T12: Plus rewrite auth system...
```

**Solution**: Stay focused:
```
T5: Noting architectural issues for separate discussion. Focusing on immediate API slowness...
```

## When NOT to Use Sequential Thinking

### ❌ Simple Factual Questions

**Instead use**: Regular conversation

**Example**:
```
Bad: "Use sequential thinking to tell me the capital of France"
Good: "What's the capital of France?"
```

---

### ❌ Casual Conversation

**Instead use**: Regular conversation

**Example**:
```
Bad: "Use sequential thinking to chat about the weather"
Good: "How's the weather looking this week?"
```

---

### ❌ When Speed is Critical

**Instead use**: Regular conversation or quick search

**Example**:
```
Bad: Emergency production issue - using sequential thinking
Good: Emergency - need quick diagnosis! (then maybe detailed analysis later)
```

---

### ❌ Code Generation Without Complexity

**Instead use**: Direct code request

**Example**:
```
Bad: "Use sequential thinking to write a simple for loop"
Good: "Write a for loop that iterates over this array"
```

## Troubleshooting Guide

### Problem: Tool Not Available

**Symptom**: "Sequential thinking tool not found"

**Solutions**:
1. Check docker-gateway is running
2. Verify MCP configuration
3. Restart Claude desktop app
4. Check Docker Desktop status

---

### Problem: Thoughts Not Connecting

**Symptom**: Each thought feels disconnected

**Solutions**:
1. Explicitly reference previous thoughts
2. Use revision to correct course
3. Add checkpoint thoughts for orientation
4. Summarize progress periodically

---

### Problem: Too Many Thoughts Needed

**Symptom**: Approaching 15+ thoughts

**Solutions**:
1. Check if problem is too broad (scope creep)
2. Consider breaking into multiple sessions
3. Skip obvious intermediate steps
4. Batch related analyses

---

### Problem: Unsure When to Stop

**Symptom**: Could keep thinking indefinitely

**Solution**: Use checklist:
```
- [ ] Problem fully understood
- [ ] Solution proposed
- [ ] Solution verified against constraints
- [ ] Edge cases considered
- [ ] No outstanding doubts
→ If all checked, stop
```

---

### Problem: Branching Too Complex

**Symptom**: Lost track of which branch is which

**Solutions**:
1. Limit to 2-3 branches maximum
2. Use clear branch_id names
3. Add synthesis thought after branching
4. Draw it out on paper if needed

---

## Best Practices to Avoid Issues

### 1. Start Conservative

Begin with 5-7 thought estimate, extend if needed.

### 2. Verify Before Finishing

Always have final verification thought.

### 3. Limit Branching Depth

Maximum 2 levels of nesting.

### 4. Be Explicit About Revisions

State what changed and why.

### 5. Stay Focused

Resist scope creep - note other issues for later.

### 6. Use Complementary Tools

Don't force everything into Sequential Thinking.

---

## When to Switch Tools

### Switch to Analysis Tool (REPL)

When you need to:
- Execute code
- Test with actual data
- Validate syntax
- Generate visualizations

### Switch to Web Search

When you need to:
- Find current information
- Gather external data
- Look up documentation
- Research unknowns

### Switch to Regular Conversation

When you need to:
- Answer simple questions
- Have casual discussion
- Provide quick information
- Communicate results

---

## Performance Optimization Tips

### Tip 1: Batch Related Thoughts

Combine when possible without losing clarity.

### Tip 2: Skip Obvious Steps

Don't narrate every minor deduction.

### Tip 3: Front-Load Constraints

State all constraints in Thought 1.

### Tip 4: Parallel Work in One Thought

```
T3: Analyzing three factors:
1. Database: No issues found
2. Cache: Hit rate too low ← Issue!
3. Network: Within normal range
```

### Tip 5: Know When to Stop

Don't over-analyze - good enough is sometimes enough.
