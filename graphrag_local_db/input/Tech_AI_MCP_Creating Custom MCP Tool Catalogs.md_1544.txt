## Overview

This guide explains how to create custom tool catalogs for the Model Context Protocol (MCP), whether using Docker Desktop or Apple's Container CLI.

**Key Concept**: A "catalog" is simply a collection of tools packaged together. You can add tools by:
1. Creating standalone MCP servers
2. Building custom container images with multiple tools
3. Extending existing tool collections

---

## Understanding Your Current Setup

### Current MCP Servers

```json
{
  "mcpServers": {
    "docker-gateway": {
      "command": "container",  // or "docker"
      "args": ["mcp", "gateway", "run"]
    },
    "text-editor": {
      "command": "uvx",
      "args": ["mcp-text-editor"]
    },
    "n8n-mcp": {
      "command": "/Users/michel/.nvm/versions/node/v20.19.5/bin/node",
      "args": ["/Users/michel/Documents/MCP_Servers/n8n-mcp/dist/mcp/index.js"]
    }
  }
}
```

**Key Points**:
- Each entry is a separate MCP server
- They can be containers, Node scripts, or Python packages
- The runtime (docker/container) only affects containerized servers
- All servers appear as tools to Claude

## Approach 1: Add Standalone MCP Servers (Recommended)

This is the **easiest and most flexible** approach. Each tool is a separate server.

### Available MCP Servers

Explore the MCP ecosystem:
- [Official MCP Servers](https://github.com/modelcontextprotocol/servers)
- [Awesome MCP Servers](https://github.com/punkpeye/awesome-mcp-servers)

### Example: Adding a Database Tool

```json
{
  "mcpServers": {
    "docker-gateway": {
      "command": "container",
      "args": ["mcp", "gateway", "run"]
    },
    "postgres": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-postgres"],
      "env": {
        "POSTGRES_CONNECTION_STRING": "postgresql://user:pass@localhost/db"
      }
    }
  }
}
```

### Example: Adding a Filesystem Tool

```json
{
  "filesystem": {
    "command": "npx",
    "args": ["-y", "@modelcontextprotocol/server-filesystem", "/Users/michel/Documents"]
  }
}
```

### Example: Adding a Python-based Tool

```json
{
  "my-python-tool": {
```

## Approach 2: Create a Custom Node.js MCP Server

Build your own MCP server with custom tools, like the n8n-mcp example.

### Project Structure

```
my-custom-mcp/
├── package.json
├── src/
│   ├── index.ts
│   └── tools/
│       ├── tool1.ts
│       └── tool2.ts
└── dist/
    └── index.js (compiled)
```

### Basic MCP Server Template

```typescript
// src/index.ts
import { Server } from "@modelcontextprotocol/sdk/server/index.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import {
  ListToolsRequestSchema,
  CallToolRequestSchema,
} from "@modelcontextprotocol/sdk/types.js";

const server = new Server(
  {
    name: "my-custom-tools",
    version: "1.0.0",
  },
  {
    capabilities: {
      tools: {},
    },
  }
);

// Define your tools
server.setRequestHandler(ListToolsRequestSchema, async () => {
  return {
    tools: [
      {
        name: "my_custom_tool",
        description: "Does something useful",
        inputSchema: {
          type: "object",
          properties: {
            input: {
              type: "string",
              description: "Input parameter",
            },
          },
          required: ["input"],
        },
      },
    ],
  };
});

// Handle tool execution
server.setRequestHandler(CallToolRequestSchema, async (request) => {
  const { name, arguments: args } = request.params;

  if (name === "my_custom_tool") {
    // Your tool logic here
    return {
      content: [
        {
          type: "text",
          text: `Result: ${args.input}`,
        },
      ],
    };
  }

  throw new Error(`Unknown tool: ${name}`);
});

// Start the server
async function main() {
  const transport = new StdioServerTransport();
  await server.connect(transport);
}

main().catch(console.error);
```

### package.json

```json
{
  "name": "my-custom-mcp",
  "version": "1.0.0",
  "type": "module",
  "main": "dist/index.js",
  "scripts": {
    "build": "tsc",
    "start": "node dist/index.js"
  },
  "dependencies": {
    "@modelcontextprotocol/sdk": "^0.5.0"
  },
  "devDependencies": {
    "@types/node": "^20.0.0",
    "typescript": "^5.0.0"
  }
}
```

### Build and Use

```bash
# Build
cd ~/Documents/MCP_Servers/my-custom-mcp
npm install
npm run build

# Add to Claude Desktop config
{
  "my-custom-mcp": {
    "command": "/Users/michel/.nvm/versions/node/v20.19.5/bin/node",
    "args": ["/Users/michel/Documents/MCP_Servers/my-custom-mcp/dist/index.js"],
    "env": {
      "MCP_MODE": "stdio"
    }
  }
}
```

## Approach 3: Build a Custom Docker/Container Image

Create a container image with multiple tools bundled together.

### Dockerfile Example

```dockerfile
FROM python:3.11-slim

# Install system dependencies
RUN apt-get update && apt-get install -y \
    curl \
    git \
    && rm -rf /var/lib/apt/lists/*

# Install Node.js (if needed)
RUN curl -fsSL https://deb.nodesource.com/setup_20.x | bash - \
    && apt-get install -y nodejs

# Install your tools
RUN pip install \
    mcp-tool-1 \
    mcp-tool-2 \
    custom-package

# Copy custom scripts
COPY ./tools /app/tools
WORKDIR /app

# Entry point
CMD ["python", "-m", "mcp.server"]
```

### Build and Use

```bash
# Build with Apple Container
container build -t my-custom-catalog .

# Or with Docker
docker build -t my-custom-catalog .

# Add to config
{
  "my-catalog": {
    "command": "container",  // or "docker"
    "args": ["run", "-i", "--rm", "my-custom-catalog"]
  }
}
```

## Approach 4: Extend the Docker Gateway

If you want to add tools to the existing gateway catalog, you'd need to:

1. **Fork/clone the gateway repository**
2. **Add your tools to the catalog**
3. **Rebuild the image**
4. **Use your custom image**

**Note**: This approach is less flexible than adding separate MCP servers.

## Best Practices

### Organization

```
~/Documents/MCP_Servers/
├── n8n-mcp/           # Existing
├── my-custom-tools/   # Your custom Node.js server
├── python-tools/      # Python-based tools
└── docker-images/     # Custom Dockerfiles
    └── my-catalog/
        └── Dockerfile
```

### Configuration Management

Keep your Claude Desktop config organized:

```json
{
  "mcpServers": {
    // Core gateway with bundled tools
    "docker-gateway": { ... },
    
    // File operations
    "text-editor": { ... },
    "filesystem": { ... },
    
    // Automation
    "n8n-mcp": { ... },
    
    // Data & APIs
    "postgres": { ... },
    "api-client": { ... },
    
    // Custom tools
    "my-custom-tools": { ... }
  }
}
```

### Environment Variables

Use environment variables for sensitive data:

```json
{
  "database-tool": {
    "command": "uvx",
    "args": ["mcp-postgres"],
    "env": {
      "DB_HOST": "localhost",
      "DB_USER": "admin",
      "DB_PASSWORD": "secret",
      "DB_NAME": "mydb"
    }
  }
}
```

## Runtime Compatibility: Docker vs Container

**Good News**: Most things work identically!

| Feature | Docker | Apple Container |
|---------|--------|-----------------|
| Run OCI images | ✅ | ✅ |
| Build images | ✅ | ✅ |
| Volume mounts | ✅ | ✅ |
| Environment variables | ✅ | ✅ |
| Port mapping | ✅ | ✅ |
| Docker-in-Docker | ✅ | ❌ (limited) |
| Networking | ✅ | ✅ (macOS 26+) |

**To switch between runtimes**, just change the command:

```json
// Using Docker
"command": "docker"

// Using Apple Container
"command": "container"
```

## Testing Your Custom Catalog

### 1. Test Standalone

```bash
# For Node.js servers
node /path/to/your/server/index.js

# For Python servers
python -m your_mcp_server

# For containers
container run -i --rm your-image
```

### 2. Check Tool Discovery

After adding to Claude Desktop config, restart Claude and ask:
"What tools do you have available?"

### 3. Test Tool Execution

Ask Claude to use one of your new tools to verify it works.

## Troubleshooting

### Server Won't Start

Check Claude Desktop logs:
- macOS: `~/Library/Logs/Claude/`
- Look for error messages from your server

### Tools Not Appearing

1. Verify the server command works standalone
2. Check the config syntax is valid JSON
3. Restart Claude Desktop completely
4. Check for port conflicts or permission issues

### Container Issues

```bash
# Check if image exists
container image ls

# Test container interactively
container run -it your-image sh

# View container logs
container logs <container-id>
```
