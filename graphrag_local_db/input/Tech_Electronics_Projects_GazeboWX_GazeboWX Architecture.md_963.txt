### Notes
- #### How the Gazebo Thermostat ESPHome Configuration Works
	1. Core Architecture
	2. Key Components
A. Time Synchronization
- Purpose: Keeps ESP32 synchronized with real time
- Why needed: Nextion display shows hourly forecasts that depend on current time
B. Home Assistant Integration
- Purpose: Pulls real weather data from Home Assistant
- Data flow: Home Assistant REST sensors → ESPHome → Nextion display
- Real data: from OpenMeteo API
C. Nextion Display Communication
- Purpose: Sends commands to Nextion touchscreen display
Uses variables like: feels_like.val=25, rain.val=30, one.dt0.val=17
D. Time Sensors for Forecasts
- Purpose: Generates hourly time labels for forecast pages
- Logic: Current time + offset (e.g., dt0 = current hour + 1)
E.  Data Flow Example
- OpenMeteo API provides weather data every 10 minutes
- Home Assistant REST sensors store this data as entities
- ESPHome Home Assistant sensors pull data from HA entities
- Lambda functions format data and send commands to Nextion
F.  Nextion display shows real-time weather on 3 pages
