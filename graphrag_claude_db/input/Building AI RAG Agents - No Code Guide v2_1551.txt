### Main Idea
- **Video Title**: The NEW Way to Build AI RAG Agents in Under 10 Minutes (no code)
- **Video URL**: https://youtu.be/idJaQIHP-s8
- Build a fully functional RAG (Retrieval-Augmented Generation) knowledge base that answers questions 24/7 using Pine Cone Assistant and n8n
- Create a client-facing chat interface using Lovable for professional presentation
- Example implementation: Alex Hormozi's "$100 Million Leads" PDF knowledge base

### Key Concepts
**RAG (Retrieval-Augmented Generation)**
- Combines language models with external knowledge retrieval
- Allows AI to answer questions based on your specific documents/data
- More powerful than standalone LLMs because it references actual source material

**Why Not Just Use Custom GPTs?**
- n8n allows connection to additional tools (email, Notion, databases, etc.)
- Can trigger automated workflows based on responses
- More control over the entire automation pipeline
- Example: "Send email to Gary with the answer" - pulls from knowledge base AND sends email

**Use Cases**
- Client onboarding automation
- Standard Operating Procedures (SOPs) documentation
- Marketing and social media content generation
- Customer support 24/7
- Internal company knowledge management

### Tools & Platforms Used
1. **n8n** - Automation workflow platform (primary orchestrator)
2. **Pine Cone Assistant** - Vector database and knowledge base storage
3. **Open Router** - Unified API access to all major LLMs (GPT, Claude, etc.)
4. **Lovable** (optional) - AI-powered front-end builder for client interface

## Step-by-Step Implementation Procedure

### Phase 1: Set Up n8n Workflow Foundation

#### Step 1: Create Chat Trigger
1. Open n8n and create new workflow
2. Click the **+ (plus)** button in center
3. Search for and select **"Chat Trigger"** or similar chat message node
4. This triggers the workflow whenever a message is sent
5. Test by typing "Hey, what's up?" to verify message reception

#### Step 2: Add AI Agent Node
1. Click **+** after the chat trigger
2. Search for **"AI Agent"**
3. Connect it to the chat trigger
4. Set **Source for prompt**: Connected Chat

---

### Phase 2: Connect LLM via Open Router

#### Step 3: Set Up Open Router Account
1. Go to [openrouter.ai](https://openrouter.ai)
2. Create account
3. Navigate to **Profile → Keys**
4. Click **"Create API Key"**
5. Name it (e.g., "RAG") and click **Create**
6. **Copy the API key**

#### Step 4: Configure Chat Model in n8n
1. In AI Agent node, find **Chat Model** section
2. Click **+** to add chat model
3. Search for and select **"Open Router"**
4. Click **"Create New Credential"**
5. Name credential (e.g., "RAG")
6. Paste API key
7. Click **Save**
8. Select model: **GPT-4o-mini** (fast and cheap)
   - For complex reasoning: Use **Claude** or **GPT-o3**

#### Step 5: Test Basic Chat
1. Send message: "Hey, what's up?"
2. Should receive response from AI agent
3. Confirms LLM connection is working

---

### Phase 3: Add Memory to Agent

#### Step 6: Configure Simple Memory
1. Click **+** after AI Agent
2. Search for **"Memory"** or **"Simple Memory"**
3. Set **Context Window**: 5-10 messages
   - This determines how many previous messages the agent remembers
4. Test memory:
   - Say: "My name is [Your Name]"
   - Then ask: "What's my name?"
   - Agent should remember and respond correctly

---

### Phase 4: Set Up Pine Cone Knowledge Base

#### Step 7: Create Pine Cone Assistant
1. Go to [app.pinecone.io](https://app.pinecone.io)
2. Create account (takes ~1 minute)
3. Navigate to **"Assistants"** section
4. Click **"Create an Assistant"**
5. Name it (e.g., "Hormozi" or your specific use case)
6. Click **"Create Assistant"**

#### Step 8: Upload Documents to Knowledge Base
1. In Pine Cone Assistant interface, go to **"Files"** tab
2. Drag and drop your documents (PDF, DOCX, etc.)
3. Click **"Import"**
4. Wait for processing (converts to vectors - numerical representations)
5. **Pro Tip**: Share this interface with clients so they can upload documents directly

#### Step 9: Get Pine Cone API Configuration
1. In Pine Cone, click **"Connect"** tab
2. Scroll to bottom, click **"Documentation"**
3. Navigate to **"Chat with your assistant"**
4. Find section: **"Chat through the standard interface"**
5. Scroll down to find the **cURL request example**
6. **Copy entire cURL request** (from "curl" to the end)

---

### Phase 5: Connect Pine Cone to n8n

#### Step 10: Add HTTP Request Tool
1. In n8n, click **+** after AI Agent
2. Search for **"HTTP Request"**
3. Select the HTTP Request node
4. Click **"Import cURL"**
5. Paste the cURL request from Pine Cone
6. Click **"Import"**

#### Step 11: Configure HTTP Request
1. **Change URL endpoint**: Replace the assistant name at the end with your actual assistant name
   - Example: `.../chat/hermosi` (use your assistant name)
2. **Update Description**: "Call this pine cone tool to answer any questions and retrieve relevant knowledge"
3. **Rename Tool**: Change to "pine_cone_tool"
   - Tool name and description help the AI agent know when to use this tool

#### Step 12: Add Pine Cone API Authentication (Secure Method)
1. In Pine Cone, go to **"API Keys"** (left sidebar)
2. Click **"Create API Key"**
3. Name it (e.g., "Hermosi")
4. Click **"Create API Key"**
5. **Copy the API key**

**In n8n:**
6. In HTTP Request node, go to **"Authentication"** section
7. Select **"Generic Credential Type"**
8. Choose **"Header Auth"**
9. Click **"Create New Credential"**
10. Name: "Pine Cone - [Your Assistant Name]"
11. **Header Name**: `Api-Key` (capital A, capital K, with dash)
12. **Value**: Paste your Pine Cone API key
13. Click **"Save"**

#### Step 13: Configure Dynamic Query
1. In HTTP Request node, find the **"Body"** or **"JSON"** field
2. Change dropdown from "JSON" to **"Expression"**
3. Delete the hardcoded question (e.g., "who is the CFO of Netflix?")
4. Type: `{{ $fromAI("searchQuery") }}`
   - This allows the AI agent to dynamically determine what to ask the knowledge base
5. Click **"Save"**

---

### Phase 6: Configure AI Agent Behavior

#### Step 14: Add System Message
1. Go back to **AI Agent** node
2. Find **"System Message"** field
3. Replace "You are a helpful assistant" with:
```
You are a helpful assistant. You MUST call the pine_cone_tool to retrieve answers for any question or task.
```
4. This instructs the agent to always query the knowledge base
5. Click **"Save"**

#### Step 15: Test Knowledge Base Integration
1. In n8n chat, ask: "What are the core four types of leads?"
2. Watch execution flow:
   - Chat Trigger receives message
   - AI Agent processes with Open Router
   - Calls pine_cone_tool (HTTP Request)
   - Pine Cone returns answer from knowledge base
   - AI Agent formats and returns response
3. Should receive accurate answer from your uploaded documents

---

### Phase 7: Add Citation Highlights (Optional but Recommended)

#### Step 16: Enable Citation Tracking
1. Go back to Pine Cone documentation
2. Find section: **"Include citation highlights in the response"**
3. Copy the JSON parameter: `"include_highlights": true`
4. In n8n, open **pine_cone_tool** (HTTP Request node)
5. Go to **Body/JSON** field (in Expression mode)
6. At the end of the JSON, add a comma, then paste:
```json
"include_highlights": true
```
7. Click **"Save"**
8. Test again - responses will now include references to specific document sections used

---

### Phase 8: Create Client-Facing Interface with Lovable (Optional)

**Why?** Clients shouldn't access n8n directly - they might break the workflow. Create a professional chat interface instead.

#### Step 17: Set Up Webhook in n8n
1. In n8n, disconnect the **Chat Trigger** from AI Agent
2. Add new **Webhook** node at the beginning
3. Set Method to **"POST"**
4. Copy the webhook URL
5. Click **"Listen for Test Event"**

#### Step 18: Update AI Agent Source
1. In AI Agent node, change **Source** from "Connected Chat" to **"Define Below"**
2. In the prompt field, use expression: `{{ $json.userMessage }}`
3. This reads the message from the webhook

#### Step 19: Add Response Webhook
1. At the END of workflow (after AI Agent), add **"Respond to Webhook"** node
2. Connect AI Agent output to this node
3. This sends the response back to the front-end

#### Step 20: Update Memory Configuration
1. In Memory node, change source to **"Define Below"**
2. Set **Chat Key**: "chat"
3. Pass in the user message from webhook

#### Step 21: Create Lovable Front-End
1. Go to [lovable.dev](https://lovable.dev) and create account
2. Start new project
3. Take screenshot of n8n chat interface for reference
4. Prompt Lovable:
```
Using the image as a reference for styling, create a simple chat interface that sends all messages in a POST request to [WEBHOOK_URL] and waits for a response.
```
5. Paste your webhook URL
6. Wait ~2 minutes for Lovable to generate the interface

#### Step 22: Test Integration
1. In Lovable chat, send test message: "test test"
2. Check n8n - should see workflow execution
3. Fix any formatting issues in Lovable:
```
This is an example of the type of response the webhook returns. Parse it so it's written in normal language: [paste example response]
```

#### Step 23: Switch to Production
1. In n8n, change webhook from **"Test"** to **"Active"** mode
2. Copy **Production URL**
3. In Lovable, update the webhook URL:
   - Remove "-test" from the URL path
   - Or use code editor: Search for "webhook" and update URL
4. Click **"Save"**
5. Test with real question
6. Share preview link with client (no need to publish/deploy)

### Troubleshooting Tips

**Agent Not Calling Pine Cone:**
- Check system message includes instruction to call pine_cone_tool
- Verify tool name matches in HTTP Request node
- Ensure description clearly explains tool purpose

**Webhook Errors:**
- Verify production URL (no "-test" suffix)
- Check JSON format in Lovable POST request
- Confirm respond_to_webhook node is at end of workflow

**Memory Issues:**
- Verify context window size is adequate
- Check that chat key is properly defined
- Ensure memory node receives user messages

**Citation Not Showing:**
- Confirm `"include_highlights": true` in JSON body
- Check Pine Cone documentation is uploaded correctly
- Verify JSON syntax (commas, brackets)

### Vector Database Alternatives to Pine Cone

#### **1. Chroma (Recommended)**
- **License**: Apache 2.0
- **Best For**: Simplicity and Python integration
- **Hosting**: Self-hosted or cloud
- **Setup Complexity**: ⭐⭐ (Easy)

**Advantages:**
- Simple Python API
- Built-in embedding functions
- Excellent documentation
- Active community
- Works great with LangChain

**Implementation in n8n:**
```python
# Python node in n8n
import chromadb
client = chromadb.Client()
collection = client.create_collection("knowledge_base")

# Add documents
collection.add(
    documents=["Your document text"],
    ids=["doc1"]
)

# Query
results = collection.query(
    query_texts=["User question"],
    n_results=3
)
```

**n8n Integration:**
- Use HTTP Request node to call Chroma REST API
- Or use Python/Code node for direct integration
- Deploy Chroma in Docker container

#### **4. pgvector (PostgreSQL Extension) - RECOMMENDED**
- **License**: PostgreSQL License
- **Best For**: When you already use Postgres or want unified database
- **Hosting**: Any Postgres hosting
- **Setup Complexity**: ⭐⭐ (Easy if you know Postgres)

**Advantages:**
- Use existing Postgres infrastructure
- ACID compliance
- Familiar SQL interface
- No separate vector database needed
- Cost-effective

**Setup:**
```sql
-- Install extension
CREATE EXTENSION vector;

-- Create table
CREATE TABLE documents (
  id serial PRIMARY KEY,
  content text,
  embedding vector(1536)
);

-- Create index
CREATE INDEX ON documents USING ivfflat (embedding vector_cosine_ops);

-- Query similar documents
SELECT content 
FROM documents 
ORDER BY embedding <-> '[query_embedding]' 
LIMIT 5;
```

**n8n Integration:**
- Use built-in Postgres node
- Execute SQL queries directly
- Generate embeddings via OpenAI or local model

**Recommended Stack with pgvector:**
```
n8n → Postgres (with pgvector) → Local embedding model (sentence-transformers)
```

### Frontend Alternatives to Lovable

#### **1. Gradio (RECOMMENDED)**
- **License**: Apache 2.0
- **Best For**: Rapid prototyping, Python-based UIs
- **Setup Complexity**: ⭐ (Very Easy)

**Advantages:**
- Create UI in ~10 lines of Python
- Built-in themes and components
- Automatic API generation
- Share publicly or keep private
- Perfect for ML/AI applications

**Implementation:**
```python
import gradio as gr
import requests

def query_knowledge_base(message, history):
    response = requests.post(
        "YOUR_N8N_WEBHOOK_URL",
        json={"userMessage": message}
    )
    return response.json()["text"]

# Create chat interface
demo = gr.ChatInterface(
    fn=query_knowledge_base,
    title="RAG Knowledge Base",
    description="Ask questions about our knowledge base",
    theme="soft"
)

demo.launch(share=True)  # Creates public link
```

**Features:**
- Chat interfaces
- File uploads
- Audio/video support
- Custom CSS
- Authentication built-in

**Hosting Options:**
- Local: `python app.py`
- HuggingFace Spaces (FREE)
- Railway
- Render
- Your own server

#### **2. Streamlit**
- **License**: Apache 2.0
- **Best For**: Data apps and dashboards
- **Setup Complexity**: ⭐ (Very Easy)

**Implementation:**
```python
import streamlit as st
import requests

st.title("RAG Knowledge Base")

# Initialize chat history
if "messages" not in st.session_state:
    st.session_state.messages = []

# Display chat messages
for message in st.session_state.messages:
    with st.chat_message(message["role"]):
        st.markdown(message["content"])

# Chat input
if prompt := st.chat_input("Ask a question"):
    # Add user message
    st.session_state.messages.append({"role": "user", "content": prompt})
    
    # Query n8n webhook
    response = requests.post(
        "YOUR_N8N_WEBHOOK_URL",
        json={"userMessage": prompt}
    )
    
    # Add assistant response
    assistant_response = response.json()["text"]
    st.session_state.messages.append({"role": "assistant", "content": assistant_response})
    
    st.rerun()
```

**Features:**
- Reactive updates
- Widgets library
- Session state management
- Custom components
- Dark/light themes

#### **3. Chainlit**
- **License**: Apache 2.0
- **Best For**: LLM-focused chat applications
- **Setup Complexity**: ⭐⭐ (Easy)

**Advantages:**
- Built specifically for LLM apps
- Streaming responses
- Multi-modal support
- Authentication built-in

**Implementation:**
```python
import chainlit as cl
import requests

@cl.on_message
async def main(message: cl.Message):
    # Query n8n
    response = requests.post(
        "YOUR_N8N_WEBHOOK_URL",
        json={"userMessage": message.content}
    )
    
    # Send response
    await cl.Message(content=response.json()["text"]).send()
```

**Features:**
- Real-time streaming
- File attachments
- Audio support
- User authentication
- Chat history persistence

**Benefits:**

- White-label ready

**PostgreSQL Schema:**
```sql
-- Users table
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    email VARCHAR(255) UNIQUE,
    created_at TIMESTAMP DEFAULT NOW()
);

-- Chat sessions
CREATE TABLE chat_sessions (
    id SERIAL PRIMARY KEY,
    user_id INTEGER REFERENCES users(id),
    created_at TIMESTAMP DEFAULT NOW()
);

-- Messages
CREATE TABLE messages (
    id SERIAL PRIMARY KEY,
    session_id INTEGER REFERENCES chat_sessions(id),
    role VARCHAR(20),
    content TEXT,
    created_at TIMESTAMP DEFAULT NOW()
);

-- Vector embeddings (using pgvector)
CREATE TABLE documents (
    id SERIAL PRIMARY KEY,
    content TEXT,
    embedding vector(1536),
    metadata JSONB,
    created_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX ON documents USING ivfflat (embedding vector_cosine_ops);
```

#### Step 4: Create Embedding Service
```python
# embedding_service.py
from sentence_transformers import SentenceTransformer
from flask import Flask, request, jsonify
import chromadb

app = Flask(__name__)
model = SentenceTransformer('all-MiniLM-L6-v2')
client = chromadb.Client()
collection = client.get_or_create_collection("knowledge_base")

@app.route('/add_document', methods=['POST'])
def add_document():
    data = request.json
    collection.add(
        documents=[data['text']],
        ids=[data['id']]
    )
    return jsonify({"status": "success"})

@app.route('/query', methods=['POST'])
def query():
    data = request.json
    results = collection.query(
        query_texts=[data['query']],
        n_results=3
    )
    return jsonify(results)

if __name__ == '__main__':
    app.run(host='0.0.0.0', port=8000)
```

#### Step 5: Create Gradio Frontend
```python
# gradio_ui.py
import gradio as gr
import requests

def chat(message, history):
    # Query embedding service
    embed_response = requests.post('http://localhost:8000/query', 
        json={'query': message}
    )
    context = embed_response.json()['documents'][0]
    
    # Query Ollama with context
    ollama_response = requests.post('http://localhost:11434/api/chat',
        json={
            'model': 'llama3.2',
            'messages': [
                {'role': 'system', 'content': f'Use this context: {context}'},
                {'role': 'user', 'content': message}
            ]
        }
    )
    
    return ollama_response.json()['message']['content']

demo = gr.ChatInterface(
    fn=chat,
    title="Open Source RAG Knowledge Base",
    description="Powered by Ollama + Chroma + Gradio"
)

demo.launch(server_name="0.0.0.0", server_port=7860, share=True)
```
