# class

### Backlink
[[Object Oriented Programming|OOP]]

### Reference

### Notes
- A [[class]] defines a blueprint
    a.  The name of the class is capitalized
    b.  Stored properties are declared
    c.  Create an initializer. It constructs new instances by initializing stored properties
    d.  You set the stored property to the passed parameter.
- Since the property and the parameter have the same name, you use the "self" keyword to distinguish between them.
- [[Functions]] defined inside a class are called methods because they have access to properties
- Swift classes use an initialization process called two-phase-initialization to guarantee that all properties are initialized before you use them.
- [[Encapsulation]]: Organizing properties and related operations in aclass
- Class types are said to encapsulate data (e.g. stored properties) and behavior (e.g. methods).
- [[Inheritance]]: A class created as a subclass of a parent class

Example:

class Piano: Instrument {
let hasPedals: Bool
// 2
static let whiteKeys = 52
static let blackKeys = 36

// 3
init(brand: String, hasPedals: Bool = false) {
self.hasPedals = hasPedals
// 4
super.init(brand: brand)
}

// 5
override func tune() -> String {
return "Piano standard tuning for (brand)."
}

override func play(_ music: Music) -> String {
// 6
let preparedNotes = super.play(music)
return "Piano playing (preparedNotes)"
}
}





a.  class Piano: Instrument {}

All of the stored properties and methods are automatically**inherited**by thePiano**child class**and available for use.

b.  static let whiteKeys = 52

The associated values of their corresponding properties*don't*change dynamically, so you mark the properties asstaticin order to reflect this



c.  super.init(brand: brand)

You use thesuperkeyword to call the parent class initializer after setting the child class stored propertyhasPedals. The super class initializer takes care of initializing inherited properties --- in this case,brand.

d.  override:

You**override**the inheritedtune()method's implementation with theoverridekeyword. This provides an implementation oftune()that doesn't callfatalError(), but rather does something specific toPiano.
