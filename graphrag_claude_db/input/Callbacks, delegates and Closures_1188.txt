# Callbacks, delegates and Closures

### Notes
-  In Swift, callback, closure, and delegate are all similar concepts, but they have some subtle differences in terms of how they are implemented and used:

- Callback: A callback is a function that is passed as an argument to another function, to be called at a later time. The callback function is usually invoked (or "called back") at some point inside the calling function, in order to complete some task or operation.
- Closure: A closure is a self-contained block of functionality that can be passed around and used in your code. Closures in Swift are similar to blocks in C and Objective-C and to lambdas in other programming languages. Closures can be passed as arguments to functions, stored in variables and constants, and can also be returned from functions.
- Delegate: A delegate is a design pattern that allows one object to communicate with another object without having to tightly couple the two objects together. In iOS and macOS, delegate pattern is extensively used for delegating work and getting notified of interesting events. In this pattern, one object, known as the delegate, is responsible for implementing certain methods or handling certain events, and another object, known as the delegator, is responsible for calling the methods or triggering the events on the delegate.
- In summary, Callbacks are functions that are passed as arguments to other functions, to be called at a later time. Closures are self-contained blocks of functionality that can be passed around and used in your code. Delegates are objects that implement certain methods or handle certain events, and are called by another object in order to accomplish a specific task or respond to an event.
