## ESPHome Conversion Specifications

**Document Version:** 1.0  
**Date:** October 17, 2025  
**Project:** Gazebo Gas Stove Thermostat Controller  
**Original Platform:** Arduino/PlatformIO with Blynk  
**Target Platform:** ESPHome with Home Assistant

## Executive Summary

Page 3 (Nextion page "three") is the primary thermostat control interface, providing local temperature display and setpoint adjustment via a Nextion HMI touchscreen. This document specifies the requirements and architecture for converting the legacy Arduino/Blynk implementation to ESPHome.

**Conversion Status:** ~85% complete
- ✅ Core thermostat logic implemented
- ✅ Temperature sensing with validation
- ✅ Safety features and failsafes
- ✅ Display update scripts
- ⚠️ Nextion touch handlers (partial)
- ❌ Perceived temperature feature
- ❌ Separate summer/winter hysteresis

## 1. Hardware Architecture

### 1.1 Display Components

**Nextion Display Page:** `three`

| Component | Type | ID | Purpose | Current Implementation |
|-----------|------|-----|---------|----------------------|
| `n0` | Number | `three.n0.val` | Desired temperature display (°C) | ✅ Updated via lambda |
| `n1` | Number | `three.n1.val` | Current temperature display (°C) | ✅ Updated via lambda |
| `Slider0` | Slider | `three.Slider0.val` | Temperature setpoint control | ❌ Touch handler needed |

### 1.2 Hardware Connections

| Component | GPIO | Type | Direction | Notes |
|-----------|------|------|-----------|-------|
| DS18B20 Temp Sensor | GPIO 4 | OneWire | Input | 1-Wire temperature sensor |
| Heating Relay | GPIO 12 | Digital | Output | LOW = OFF, HIGH = ON |
| Nextion Display TX | GPIO 17 | UART | Output | TXD2 pin |
| Nextion Display RX | GPIO 16 | UART | Input | RXD2 pin |

**UART Configuration:**
- Baud Rate: 9600
- Protocol: 8N1 (8 data bits, no parity, 1 stop bit)
- Buffer Size: 1024 bytes (increased for Nextion data)

## 2. Functional Requirements

### 2.1 Temperature Sensing

**Primary Sensor:** Dallas DS18B20 digital temperature sensor

**Requirements:**
- Update interval: 10 seconds
- Measurement range: -55°C to +125°C (sensor spec)
- Operating range: -10°C to +50°C (thermostat use)
- Accuracy: ±0.5°C
- Resolution: 0.1°C display precision

**Temperature Processing Pipeline:**
1. **Raw Reading** - Read sensor value every 10s
2. **Validation** - Check for NaN, out-of-range values
3. **Correction** - Apply user-configurable offset (-10°C to +10°C)
4. **Smoothing** - Limit changes to ±1°C per reading
5. **Averaging** - Average with previous reading
6. **Perceived Temp** - Apply humidity adjustment (optional)
7. **Display Update** - Send to Nextion display

### 2.2 Bad Read Handling

**Implementation Status:** ✅ Fully Implemented

```yaml
# From thermostat.yaml lines 18-75
sensor:
  - platform: template
    name: "Gazebo Temperature"
    lambda: |-
      // Validation → Bad Read Counting → Malfunction Detection
      // Smoothing → Fallback to Last Valid Reading
```

**Bad Read Logic:**
1. **Detection:** NaN or out-of-range (-40°C to +80°C)
2. **Counter:** Increment `sensor_bad_reads` global variable
3. **Threshold:** 10 consecutive bad reads triggers malfunction
4. **Fallback:** Use last valid reading when sensor fails
5. **Recovery:** Auto-reset counter on successful read
6. **Safety:** Force heating OFF on malfunction

**Monitoring Entities:**
- `sensor.sensor_bad_read_count` - Number of consecutive failures
- `sensor.last_valid_temperature` - Last good temperature reading
- `binary_sensor.sensor_malfunction` - Malfunction status flag
- `text_sensor.sensor_status` - Human-readable status

## 3. Thermostat Control Logic

### 3.1 Operating Modes

**Mode Selection:** `select.thermostat_mode`

| Mode | Behavior | Relay Control |
|------|----------|---------------|
| **Off** | No heating, relay forced OFF | Manual control |
| **Heat** | Automatic hysteresis control | Algorithm controlled |
| **Manual** | Manual Run switch takes control | Switch controlled |

### 3.2 Hysteresis Control

**Current Implementation:** Single hysteresis value (Winter mode only)

**Legacy Arduino Implementation:**
- **Winter Mode:** Uses `Hysteresis_W` (2-6°C, stored in EEPROM address 1)
- **Summer Mode:** Uses `Hysteresis_S` (2-6°C, stored in EEPROM address 2)
  - Note: Summer mode is for cooling, not currently used in gas stove application

**ESPHome Implementation:**
```yaml
# thermostat.yaml lines 206-215
number:
  - platform: template
    name: "Hysteresis"
    id: hysteresis
    min_value: 1
    max_value: 5
    step: 0.5
    initial_value: 2
    restore_value: true
```

**Control Algorithm (lines 484-509):**
```
Heating ON when:  current_temp < (desired_temp - hysteresis)
Heating OFF when: current_temp >= (desired_temp + hysteresis)
```

**Example:** Desired = 20°C, Hysteresis = 2°C
- Heat turns ON at: 18°C (20 - 2)
- Heat turns OFF at: 22°C (20 + 2)
- Deadband width: 4°C (prevents rapid cycling)

### 3.3 Priority Hierarchy

**Control Logic Order (from thermostat.yaml lines 342-509):**

1. **🚨 Sensor Malfunction** (Highest Priority)
   - Force heating OFF immediately
   - Non-recoverable until sensor repairs

2. **🛑 Manual Stop Switch**
   - Force heating OFF
   - Overrides all other controls

3. **🔴 Manual Run Switch**
   - Force heating ON
   - Overrides automatic control

4. **⚙️ Mode Check**
   - Only run if mode = "Heat"
   - Turn OFF if mode = "Off"

5. **🏠 Home/Away Status**
   - Only heat when Home = ON
   - Turn OFF when Away

6. **⏰ Timer Schedule**
   - Check if within schedule window
   - Turn OFF if outside schedule

7. **🔥 Hysteresis Algorithm**
   - Standard thermostat control
   - With minimum off time check

### 3.4 Safety Features

**Implementation Status:** ✅ All Implemented

| Safety Feature | Trigger Condition | Action | Location |
|----------------|-------------------|--------|----------|
| Sensor Malfunction | 10 consecutive bad reads | Force OFF, disable heating | Lines 347-357 |
| Maximum Runtime | 1 hour continuous heating | Force OFF | Lines 463-469 |
| Temperature Runaway | Temp > (desired + 5°C) | Force OFF | Lines 472-479 |
| Minimum Off Time | 300s default (disabled in testing) | Delay next heating cycle | Lines 486-490 |

## 5. Perceived Temperature Feature

### 5.1 Overview

**Status:** ❌ Not Yet Implemented in ESPHome

**Purpose:** Adjust thermostat behavior based on humidity to account for human comfort perception

**Legacy Implementation:** thermostat.cpp lines 28-31
```cpp
// Use "perceived temperature" offset (when turned on in SETTINGS)
if(UsePerceivedTemp == true && Winter == false && ReadF > 20 && Humidity > 40){
    TempAvg += int((Humidity - 40) / 10);
}
```

### 5.2 Algorithm Specification

**Activation Conditions:**
- ✅ UsePerceivedTemp = true (user-enabled setting)
- ✅ Winter = false (Summer mode only)
- ✅ Temperature > 20°C (above comfort threshold)
- ✅ Humidity > 40% (significant humidity effect)

**Calculation:**
```
perceived_offset = (humidity - 40) / 10
perceived_temp = actual_temp + perceived_offset
```

**Examples:**
| Actual Temp | Humidity | Perceived Offset | Perceived Temp |
|-------------|----------|------------------|----------------|
| 22°C | 40% | 0°C | 22°C |
| 22°C | 50% | +1°C | 23°C |
| 22°C | 60% | +2°C | 24°C |
| 22°C | 70% | +3°C | 25°C |

### 5.3 ESPHome Implementation Plan

**Required Components:**

1. **Humidity Sensor Integration**
   - Source: Home Assistant sensor `sensor.nh_meteo_humidity` (already imported)
   - Alternative: DHT22 sensor (legacy hardware had DHT11, now using DS18B20)

2. **Toggle Switch**
```yaml
switch:
  - platform: template
    name: "Use Perceived Temperature"
    id: use_perceived_temp
    restore_mode: RESTORE_DEFAULT_OFF
    optimistic: true
```

3. **Season/Mode Selector**
```yaml
select:
  - platform: template
    name: "Season Mode"
    id: season_mode
    options:
      - "Winter"
      - "Summer"
    initial_option: "Winter"
    restore_value: true
```

4. **Perceived Temperature Calculation**
```yaml
sensor:
  - platform: template
    name: "Perceived Temperature"
    id: perceived_temp
    unit_of_measurement: "°C"
    accuracy_decimals: 1
    lambda: |-
      float actual = id(gazebo_temp).state;
      float humidity = id(nh_meteo_humidity).state;
      
      // Check activation conditions
      if (id(use_perceived_temp).state && 
          id(season_mode).state == "Summer" &&
          actual > 20.0 &&
          humidity > 40.0) {
        
        float offset = (humidity - 40.0) / 10.0;
        float perceived = actual + offset;
        
        ESP_LOGD("perceived_temp", "Actual: %.1f°C, Humidity: %.0f%%, Offset: +%.1f°C, Perceived: %.1f°C",
                 actual, humidity, offset, perceived);
        return perceived;
      }
      
      return actual;  // Return actual temp if conditions not met
```

5. **Thermostat Logic Modification**
```yaml
# In thermostat control interval, replace:
#   float current_temp = id(gazebo_temp).state;
# With:
#   float current_temp = id(use_perceived_temp).state ? 
#                        id(perceived_temp).state : 
#                        id(gazebo_temp).state;
```

## 6. Data Persistence & State Management

### 6.1 EEPROM to ESPHome Migration

**Legacy Arduino EEPROM Layout:**

| Address | Size | Parameter | Range | ESPHome Equivalent |
|---------|------|-----------|-------|-------------------|
| 0 | 1 byte | TempCorrection (+10 offset) | 0-20 (actual: -10 to +10) | `number.temp_correction` |
| 1 | 1 byte | Hysteresis_W | 2-6°C | `number.hysteresis` |
| 2 | 1 byte | Hysteresis_S | 2-6°C | *Not yet implemented* |
| 3 | 1 byte | TempDes | 10-30°C | `number.temp_desired` |
| 4 | 1 byte | Winter (season mode) | 0/1 | `select.thermostat_mode` + `select.season_mode` (proposed) |
| 5 | 1 byte | UsePerceivedTemp | 0/1 | `switch.use_perceived_temp` (proposed) |
| 6 | 1 byte | DashboardColor | 1-5 | *Not applicable (Blynk only)* |
| 10-15 | 6 bytes | BeginTimer (long) | seconds | `number.timer_start_hour` (simplified) |
| 16-21 | 6 bytes | EndTimer (long) | seconds | `number.timer_end_hour` (simplified) |

**ESPHome Persistence Strategy:**

All parameters use `restore_value: true` attribute, which stores values in ESP32 flash memory:

```yaml
number:
  - platform: template
    name: "Desired Temperature"
    id: temp_desired
    restore_value: true  # ← Replaces EEPROM persistence
    optimistic: true
```

**Advantages of ESPHome Approach:**
- ✅ No manual EEPROM address management
- ✅ Automatic write leveling (flash wear protection)
- ✅ Type-safe storage (no byte packing/unpacking)
- ✅ Automatic restore on boot
- ✅ Integration with Home Assistant

### 6.2 State Variables

**Global Variables (thermostat.yaml lines 269-308):**

| Variable | Type | Purpose | Initial Value | Persisted |
|----------|------|---------|---------------|-----------|
| `heating_state` | bool | Current relay state | false | No |
| `last_heating_change` | unsigned long | Timestamp of last relay change (ms) | 0 | No |
| `heating_start_time` | unsigned long | When current heating cycle started | 0 | No |
| `max_heating_time` | unsigned long | Maximum continuous run time | 3600000 (1 hour) | No |
| `min_heating_off_time` | unsigned long | Minimum time between cycles | 0 (disabled) | No |
| `sensor_bad_reads` | int | Consecutive sensor failures | 0 | No |
| `sensor_last_valid` | float | Last valid temperature | 20.0 | Yes |
| `sensor_malfunction` | bool | Sensor failure flag | false | No |
| `temp_smoothed` | float | Smoothed temperature value | 20.0 | No |

**Runtime-Only Variables:**
- Reset on boot/restart
- Used for safety timing and state tracking
- Not exposed to Home Assistant (internal use only)

**Persisted Variables:**
- `sensor_last_valid`: Survives reboot to maintain temperature continuity
- All `number`, `select`, `switch` entities with `restore_value: true`

## 14. Performance & Optimization

### 14.1 Update Intervals

| Component | Update Rate | Rationale |
|-----------|-------------|-----------|
| Temperature sensor | 10s | Balance between responsiveness and sensor polling |
| Thermostat control | 10s | Synchronized with sensor updates |
| Display update | 10s | Match thermostat control interval |
| WiFi signal | 60s | Low priority monitoring |
| Weather data | Variable | Controlled by Home Assistant integration |

### 14.2 Memory Usage

**Global Variables:** 9 variables × ~8 bytes = 72 bytes
**String Buffers:** Nextion commands ~256 bytes
**Lambda Stack:** Estimated 2KB per function
**Total RAM Usage:** ~3-5KB (ESP32 has 520KB)

**Flash Persistence:**
- Each `restore_value: true` entity: ~8-16 bytes
- Total saved state: ~100 bytes
- ESP32 flash wear leveling: 1M+ writes before failure

### 14.3 Network Optimization

**Home Assistant API:**
- Uses native API (faster than MQTT)
- Automatic reconnection on WiFi loss
- Continues thermostat operation during disconnection

**OTA Updates:**
- Safe mode fallback (3 attempts before rollback)
- Heating forced OFF during update (safety)
- Typically completes in 30-60 seconds

## 15. Troubleshooting Guide

### 15.1 Common Issues

**Issue: Display not updating**
- Check UART wiring (GPIO 16/17)
- Verify baud rate (9600)
- Check component names in HMI file
- Review logs: `esphome logs gazebo-thermostat.yaml`

**Issue: Sensor reading NaN**
- Check OneWire connection (GPIO 4)
- Verify DS18B20 power (3.3V or parasitic)
- Check 4.7kΩ pullup resistor
- View `sensor.sensor_bad_read_count` in Home Assistant

**Issue: Heating not turning on**
- Check mode = "Heat"
- Verify Home status = ON
- Check timer schedule (if enabled)
- Review logs for thermostat control decisions
- Confirm temperature below (desired - hysteresis)

**Issue: Heating runs continuously**
- Check sensor reading is valid
- Verify temperature reaching setpoint
- Check for temperature runaway (safety engaged)
- Confirm hysteresis value is reasonable (>1°C)

### 15.2 Diagnostic Commands

**View live logs:**
```bash
esphome logs gazebo-thermostat.yaml
```

**Force temperature update:**
```bash
# In Home Assistant Developer Tools > Services
service: esphome.gazebo_thermostat_component_update
data:
  component: gazebo_temp
```

**Test relay manually:**
```bash
# Turn ON
service: switch.turn_on
target:
  entity_id: switch.gazebo_relay

# Turn OFF
service: switch.turn_off
target:
  entity_id: switch.gazebo_relay
```
