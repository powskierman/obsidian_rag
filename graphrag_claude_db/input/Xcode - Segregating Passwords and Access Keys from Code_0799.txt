# Xcode - Segregating Passwords and Access Keys from Code
Date: 2023-10-03

### Notes

#### Step 1: Create the `Secrets.plist` File

1. In Xcode, go to File > New > File.
2. Choose "Property List" and name it `Secrets.plist`.
3. In the plist, create an entry with the Key as `HomeAssistantAccessToken` and Value as your access token.

#### Step 2: Exclude `Secrets.plist` from Version Control

To prevent the secrets from being checked into a public source control, add `Secrets.plist` to your `.gitignore`:

```gitignore
Secrets.plist
```

#### Step 3: Modify the Code

Replace the hardcoded access token in your code with a function that reads from the `Secrets.plist` file:

```swift TI:"Example of use of secret.plist" "FOLD" 
public class HomeAssistantWebSocket {
    // ... [other code]

    private func getAccessToken() -> String? {
        if let path = Bundle.main.path(forResource: "Secrets", ofType: "plist"),
           let dict = NSDictionary(contentsOfFile: path) as? [String: Any] {
            return dict["HomeAssistantAccessToken"] as? String
        }
        return nil
    }

    func authenticate() {
        guard let accessToken = getAccessToken() else {
            print("Failed to retrieve access token.")
            return
        }

        let authMessage = [
            "type": "auth",
            "access_token": accessToken
        ]
        
        if let data = try? JSONSerialization.data(withJSONObject: authMessage, options: []),
            let jsonString = String(data: data, encoding: .utf8) {
            print("Authenticating with message:", jsonString)
            socket.write(string: jsonString)
        } else {
            print("Failed to serialize authentication message.")
        }
    }

    // ... [other code]
}
```

Now, the access token is stored in `Secrets.plist`, and the code reads from that plist file to get the access token. It’s a safer practice than hardcoding sensitive values directly in your source code, but always remember that storing sensitive data locally on an app isn't completely secure, especially if the plist isn't encrypted.
