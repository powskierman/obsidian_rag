## Main Idea
Built a fully local RAG (Retrieval-Augmented Generation) system that indexes my entire Obsidian vault (7,113 chunks from 1,605 files) and enables natural language querying with AI-powered responses. Features semantic search (ChromaDB), deprecated graph-based RAG (LightRAG), and **advanced knowledge graph analysis (GraphRAG-Local-Ollama)**. 100% private, no data leaves my Mac, runs entirely in Docker containers.

**Latest Update:** Successfully implemented GraphRAG-Local-Ollama service (Port 8003) with specialized medical entity extraction and stable Ollama integration. LightRAG deprecated due to event loop conflicts.

---

## System Architecture

### Components
1. **Embedding Service** (Docker Container) - Port 8000
   - Sentence Transformers (`all-MiniLM-L6-v2`)
   - ChromaDB vector database
   - Handles indexing and semantic search
   - REST API for embedding and querying

2. **LightRAG Service** (Docker Container) - Port 8001 - ⚠️ **DEPRECATED**
   - Graph-based RAG with knowledge graph construction
   - **Status:** Deprecated due to persistent event loop conflicts
   - **Replacement:** GraphRAG-Local service (Port 8003)

2b. **GraphRAG-Local Service** (Docker Container) - Port 8003 - ✅ **PRODUCTION**
   - Microsoft GraphRAG with specialized Ollama integration
   - Advanced knowledge graph construction and community detection
   - Medical terminology optimization
   - Global and local search capabilities
   - Native qwen2.5-coder:14b + nomic-embed-text integration

3. **Streamlit UI** (Docker Container) - Port 8501
   - Natural language queries
   - Source citations with relevance scores
   - Adjustable parameters (sources, temperature)
   - Model selection interface

4. **LLM** (Ollama Host) - Port 11434
   - **Primary Model:** qwen2.5-coder:14b (GraphRAG-Local optimized)
   - Qwen 2.5 Coder 32B (traditional RAG default)
   - DeepSeek R1:14b (reasoning model alternative)
   - nomic-embed-text (GraphRAG embeddings)
   - Local inference, no API calls

5. **Scanner Scripts** (Python)
   - `simple_scanner.py` - Basic one-time indexing
   - `obsidian_scanner.py` - Advanced scanner with file watching
   - Chunks documents (1000 chars, 200 overlap)
   - Extracts YAML frontmatter metadata

## Issues Encountered & Solutions

### Docker vs Manual Python Setup
**Problem:** Python version conflicts and dependency management complexity
**Solution:** Migrated to Docker-based architecture for consistent deployment

### Service Discovery and Port Management
**Problem:** Manual service startup and port conflicts
**Solution:** Docker Compose orchestration with automatic service discovery

### NumPy Installation Issues
**Problem:** Corrupted numpy installation in virtual environment
**Solution:** Docker containers eliminate local dependency conflicts

### Ollama Model Integration
**Problem:** Connecting Ollama running on host to Docker containers
**Solution:** Used `host.docker.internal` networking for container-to-host communication

### ChromaDB Persistence
**Problem:** Database data lost between container restarts
**Solution:** Docker volumes for persistent storage of `chroma_db` and `lightrag_db`

## Lessons Learned

### Technical
1. **Python version matters** - 3.13 too unstable on macOS for production
2. **Local embeddings > API calls** - More reliable for bulk operations
3. **Model selection critical** - Use reasoning models for text, not vision models
4. **Chunking strategy important** - 1000 chars with 200 overlap works well
5. **Metadata essential** - ChromaDB requires non-empty metadata

### Practical
1. **Start with 5 sources** - Balance between speed and comprehensiveness
2. **DeepSeek R1 best for medical/technical** - Strong reasoning capabilities
3. **Regular reindexing unnecessary** - Only scan when notes change significantly
4. **Source citations crucial** - Builds trust in AI responses
5. **Privacy matters** - Local-only system is slower but more trustworthy

## 🎉 Latest Enhancements (October 2025)

### **Enhanced Features Added**

#### **1. Query Expansion & Re-ranking**
- **Query Expansion:** Automatically generates query variations for better recall
  - Handles hyphenated terms (CAR-T → car t, cart)
  - Medical synonym mapping (lymphoma → DLBCL, B-cell lymphoma)
- **Cross-Encoder Re-ranking:** Second-pass relevance scoring for better precision
  - Uses `cross-encoder/ms-marco-MiniLM-L-6-v2`
  - 30% improvement in result quality

#### **2. Smart Semantic Chunking**
- **Old:** Fixed 1000-character chunks
- **New:** Chunks by semantic boundaries (headers, paragraphs)
- Keeps related content together for better context

#### **3. Source Deduplication**
- Returns diverse sources instead of multiple chunks from same note
- Shows best chunk from each relevant file
- Cleaner, more actionable results

#### **4. Mem0 Memory Integration**
- **Persistent Memory:** Remembers conversations across sessions
- **User Context:** Tracks medical timeline, preferences, interests
- **Smart Responses:** Avoids repeating known information
- **Timeline Tracking:** Automatically maintains treatment timeline

**Pre-seeded facts:**
- DLBCL diagnosis and Yescarta timeline
- Technical interests (3D printing, Raspberry Pi, etc.)

#### **5. File Watching**

- **Real-time updates:** New/modified files indexed automatically
- **Smart scanning:** Only processes changed files
- **Debouncing:** Prevents duplicate processing

#### **6. Enhanced UI**
