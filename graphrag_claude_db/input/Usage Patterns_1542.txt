## Basic Flow Patterns

### Linear Flow
```
1. Understand problem [1/5]
2. Identify constraints [2/5]
3. Consider solution [3/5]
4. Evaluate solution [4/5]
5. Final answer [5/5] ✓
```

### Flow with Revision
```
1. Understand problem [1/5]
2. Try approach A [2/5]
3. [REVISION] A won't work [3/6]
4. Try approach B [4/6]
5. Verify B [5/6]
6. Final answer [6/6] ✓
```

### Flow with Branching
```
1. Problem [1/5]
2. Two approaches [2/7]
3. [Branch A] Explore sync [3/7]
4. [Branch A] Issues [4/7]
5. [Branch B] Explore async [5/7]
6. [Branch B] Works! [6/7]
7. Select B [7/7] ✓
```

### Flow with Dynamic Adjustment
```
1. Initial analysis [1/5]
2. More complex, adjust to 8 [2/8]
3-4. Exploring [3-4/8]
5. Found shortcut, reduce to 6 [5/6]
6. Final answer [6/6] ✓
```

## Common Reasoning Patterns

### 1. Hypothesis-Driven
```
1. Observe symptoms
2. Generate hypothesis
3. Test hypothesis
4. If failed → New hypothesis
5. If succeeded → Verify
6. Final answer
```

### 2. Divide and Conquer
```
1. Break into subproblems
2-4. Solve each subproblem
5. Synthesize solutions
6. Verify complete solution
7. Final answer
```

### 3. Iterative Refinement
```
1. Initial rough solution
2. Identify weaknesses
3. Refine solution
4. Re-evaluate
5. Repeat until satisfied
6. Final polished solution
```

### 4. Comparative Analysis
```
1. State problem
2. Identify options A, B, C
3-5. Explore each option
6. Compare options
7. Select best
8. Final recommendation
```

## Best Practices

1. **Start Reasonable**: 5-7 thoughts for most problems
2. **Be Honest**: Acknowledge uncertainty
3. **Revise When Needed**: Don't persist with errors
4. **Branch Wisely**: Only for truly different approaches
5. **Adjust Dynamically**: Change total_thoughts as you learn
6. **Finish When Satisfied**: Verify before concluding
7. **Filter Information**: Focus on what matters
8. **Test Hypotheses**: Explicit verification

## When to Stop

### Good Indicators ✅
- All constraints satisfied
- Hypothesis verified
- Edge cases considered
- Alternatives evaluated
- Complete solution
- No outstanding questions

### Bad Indicators ❌
- Unverified assumptions
- Incomplete analysis
- Unexplored alternatives
- Low confidence (<90%)
- Missing verification

## Anti-Patterns

❌ **Analysis Paralysis**: Too many thoughts, no progress
❌ **Premature Conclusion**: Stopping without verification
❌ **Revision Spiral**: Constant revision, no forward movement
❌ **Ignoring Constraints**: Not checking requirements
❌ **Branching Overload**: Too many branches to track

## Pattern Selection Guide

| Problem Type | Pattern |
|--------------|---------|
| Debugging | Hypothesis-Driven |
| System Design | Divide and Conquer |
| API Design | Iterative Refinement |
| Tech Choice | Comparative Analysis |
| Optimization | Iterative Refinement |

## Typical Flow Patterns

### Pattern 1: Basic Linear Flow

```
1. Understand the problem [1/5]
2. Identify key constraints [2/5]
3. Consider solution approach [3/5]
4. Evaluate approach against constraints [4/5]
5. Provide final answer [5/5] ✓
```

**When to use**: Straightforward problems with clear path

---

### Pattern 2: Flow with Revision

```
1. Understand the problem [1/5]
2. Identify key constraints [2/5]
3. Consider solution A [3/5]
4. [REVISION of thought 3] Actually, solution A won't work because... [4/6]
5. Consider solution B instead [5/6]
6. Provide final answer [6/6] ✓
```

**When to use**: When initial approach has flaws

---

### Pattern 3: Flow with Branching

```
1. Understand the problem [1/5]
2. Two possible approaches identified [2/7]
3. [Branch A] Explore synchronous approach [3/7]
4. [Branch A] Issues with blocking [4/7]
5. [Branch B from thought 2] Explore async approach [5/7]
6. [Branch B] This works better! [6/7]
7. Final answer based on async approach [7/7] ✓
```

**When to use**: Multiple viable approaches exist

---

### Pattern 4: Flow with Dynamic Adjustment

```
1. Initial analysis [1/5]
2. Deeper than expected... adjusting to 8 thoughts [2/8]
3. Exploring factor A [3/8]
4. Exploring factor B [4/8]
5. Found shortcut! Reducing to 6 thoughts [5/6]
6. Final answer [6/6] ✓
```

**When to use**: Problem complexity unclear initially

## Common Reasoning Patterns

### Pattern 1: Hypothesis-Driven Investigation

```
1. State the problem
2. Generate initial hypothesis
3. Test hypothesis
4. If fails → revise hypothesis (back to step 2)
5. If succeeds → verify thoroughly
6. Provide final answer
```

**Best for**: Debugging, root cause analysis, diagnostics

---

### Pattern 2: Divide and Conquer

```
1. Break problem into subproblems
2. Solve each subproblem (may branch)
3. Synthesize solutions
4. Verify complete solution
5. Final answer
```

**Best for**: Complex problems, system design, architecture

---

### Pattern 3: Iterative Refinement

```
1. Initial rough solution
2. Identify weaknesses
3. Refine solution
4. Re-evaluate (repeat 2-3 if needed)
5. Final polished solution
```

**Best for**: Optimization, design, creative solutions

---

### Pattern 4: Comparative Analysis

```
1. State problem
2. Identify options (A, B, C)
3. [Branch A] Explore option A
4. [Branch B] Explore option B
5. [Branch C] Explore option C
6. Compare branches
7. Select best option
8. Final recommendation
```

**Best for**: Decision-making, strategy, trade-off analysis

## Best Practices

### 1. Start with a Reasonable Estimate

```json
{
  "thought_number": 1,
  "total_thoughts": 5,  // Start with 5-7 thoughts for most problems
  "thought": "Initial analysis..."
}
```

**Tip**: It's better to start conservative and extend than over-estimate.

---

### 2. Be Honest About Uncertainty

```json
{
  "thought": "I'm not certain if this approach will work, but let me explore it..."
}
```

**Tip**: Expressing uncertainty enables better revision later.

---

### 3. Revise When Needed

Don't be afraid to backtrack:

```json
{
  "thought_number": 5,
  "is_revision": true,
  "revises_thought": 3,
  "thought": "Actually, my assumption in thought 3 was incorrect because..."
}
```

**Tip**: Revision is a feature, not a bug!

---

### 4. Use Branching for Alternatives

When multiple approaches are viable:

```json
{
  "branch_from_thought": 2,
  "branch_id": "async_approach",
  "thought": "Let's explore the async alternative..."
}
```

**Tip**: Branching makes trade-offs explicit.

---

### 5. Adjust total_thoughts Dynamically

```json
// Started with 5, realized it's more complex
{
  "thought_number": 3,
  "total_thoughts": 8,  // Increased from 5
  "thought": "This is more complex than initially thought..."
}
```

**Tip**: Adjusting shows adaptive thinking.

---

### 6. Only Finish When Satisfied

```json
{
  "thought_number": 7,
  "total_thoughts": 7,
  "next_thought_needed": false,  // Only when truly done!
  "thought": "Final verified answer: ..."
}
```

**Tip**: Don't rush to finish - thoroughness matters.

---

### 7. Filter Irrelevant Information

```json
{
  "thought": "Ignoring the tangential details about X, the core issue is Y..."
}
```

**Tip**: Explicitly noting what you're filtering helps focus.

---

### 8. Generate and Verify Hypotheses

```json
// Generate
{
  "thought": "Hypothesis: The bottleneck is in the database layer"
}

// Verify
{
  "thought": "Testing hypothesis against metrics... confirmed: 90% of latency is DB queries"
}
```

**Tip**: Separate hypothesis generation from verification.

## When to Stop Thinking

### Good Stopping Points

✅ **All constraints satisfied**
✅ **Hypothesis verified against requirements**
✅ **Solution is complete and correct**
✅ **No outstanding questions or doubts**
✅ **Alternative approaches considered**
✅ **Edge cases addressed**

### Bad Stopping Points

❌ **"This seems about right"** (not verified)
❌ **"I'm 80% confident"** (not certain)
❌ **"Haven't considered edge case X"** (incomplete)
❌ **"Alternative Y might be better"** (unexplored)

---

## Anti-Patterns to Avoid

### 1. Premature Conclusion

**Problem**: Finishing before thorough verification

**Solution**: Add verification step before concluding

### 2. No Revision When Needed

**Problem**: Sticking with flawed initial approach

**Solution**: Use `is_revision` to backtrack

### 3. Ignoring Complexity

**Problem**: Not adjusting `total_thoughts` as complexity emerges

**Solution**: Dynamically adjust estimates

### 4. Over-Branching

**Problem**: Creating too many branches without synthesis

**Solution**: Limit to 2-3 meaningful branches

### 5. Lack of Verification

**Problem**: Proposing solution without testing against constraints

**Solution**: Always add verification step

## Progression Indicators

### How to Track Progress

```
[1/5]  - Early (20%)
[3/5]  - Midpoint (60%)
[5/5]  - Complete (100%)
[3/8]  - Adjusted complexity (37.5%)
```

**Tip**: Progress indicators help users follow along.

---

## Quality Checklist

Before setting `next_thought_needed = false`, verify:

- [ ] Problem fully understood
- [ ] All constraints identified
- [ ] Solution addresses root cause
- [ ] Solution verified against constraints
- [ ] Edge cases considered
- [ ] Alternative approaches evaluated
- [ ] No outstanding doubts
