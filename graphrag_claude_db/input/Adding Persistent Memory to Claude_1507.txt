### Main Idea
- Adding persistent memory to Claude Desktop requires configuring local memory files or connecting an external MCP memory server.

- 
### Notes
- There are two main approaches based on current best practices and tool support.

​
Option 1: Native Project Memory (Local Files)
- Claude Desktop already supports lightweight file-based memory out of the box.
- Steps:
	Create a CLAUDE.md file in your working directory or ~/.claude/ folder.
    Include project information, goals, coding practices, and reusable system instructions.

    Add more CLAUDE.md or CLAUDE.local.md files in subdirectories if you want local context specific to each project folder. <mark style="background: #FFF3A3A6;">Claude recursively reads all available memory files when engaged in that context.
</mark>
	    <mark style="background: #FFB8EBA6;">Use `/memory` to open or edit a memory file directly in your system editor.</mark>

    Quickly store new memories by starting a message with # (for example, # Remember to always use async file I/O). Claude will prompt you to select a memory file to append this note.

    ​This setup works well for single projects and personal organization.
- Option 2: Add a Memory MCP Server

- To enable persistent, searchable memory across all Claude Desktop sessions, connect a Model Context Protocol (MCP) server.
- Common servers:

	WhenMoon Memory MCP

    ebailey78/mcp-memory

    Mem0 OpenMemory

- Setup Steps:
	Locate your configuration file:
    macOS: ~/Library/Application Support/Claude/claude_desktop_config.json
    Add your memory MCP server details, for example:

```json
{
  "mcpServers": {
    "memory": {
      "command": "python",
      "args": ["-m", "memory_mcp"],
      "env": {
        "MEMORY_FILE_PATH": "/path/to/your/memory.json"
      }
    }
  }
}```

- Restart Claude Desktop, then confirm a new tool (like create_memory or ask_memory) appears in the Tools list.

- Persist and query data directly from chats. Claude will retain and recall information across sessions, projects, or even devices (if cloud-synced).

- Option 3: Using Pieces Memory Connector

If you prefer an integrated tool instead of self-hosting:

    - Install with
    `brew install pieces-cli`

    - Run pieces MCP setup

    - Relaunch Claude Desktop — you’ll see “Pieces” as a connector with two tools:

        `ask_pieces_ltm`: query stored memories

        `create_pieces_memory`: save new ones.

        ​

Each method — local files, self-hosted MCP, or external connectors — extends Claude Desktop’s context persistence, from project-specific recall to full long-term semantic memory.
